# VisionCortex 端到端视频分析交付手册

本手册覆盖首次安装、站点准备、任务提交与成果验收。普通分析用户使用浏览器；管理员负责模型、运行环境、存储和服务。本文描述当前入口与验收方法，不附带现场运行数据或默认生产站点。

## 1. 首次安装与生产准备分别验收

首次克隆按本地启动说明创建 Python 3.11 或 3.12 环境，安装核心依赖，再运行诊断与启动器。默认 `development-local.yaml` 使用 `demo` 模式和仓库内的本地目录；示例索引只有表头，没有预置现场设备或历史档案。

首页“实验运行概览”出现空档案属于正常首次状态。“服务状态”中的本地目录可用、视频处理待配置和真实分析环境未配置，应分别理解为存储已创建、模型环境尚未准备。页面启动不代表真实模型或视频分析通过。

| 证据 | 可以证明的范围 |
| --- | --- |
| 安装与诊断通过 | 解释器、核心依赖、入口和配置预检 |
| 浏览器页面可用 | 当前服务的页面交付；不能代替模型调用 |
| 确定性或合成测试 | 对应结构、接口与故障保护行为 |
| 真实模型调用回执 | 本次模型和运行环境实际执行 |
| 真实视频与独立真值验收 | 对应输入、版本和评估范围的质量 |

结论使用 `PROVEN`、`PARTIAL_EVIDENCE` 或 `NOT_PROVEN`，并写明未完成的门禁。没有实际视频、模型调用和质量回执时，不能把页面或测试结果外推为正式分析质量。

## 2. 管理员准备站点

### 固定版本与私有配置

记录完整源码 SHA、解释器、依赖和目标硬件。真实部署使用明确指定的私有站点配置；公开生产配置文件是未配置模板，不能直接作为已准备的生产站点。

站点配置需要核对：输入索引、设备视角、模型与引擎、归档、本地缓存、staging、运行目录、监听范围、认证和容量上限。现场地址、账号、绝对路径与凭据不进入公共仓库。本地 SQLite、队列和活动模型位于本地磁盘；NAS 挂载和来源身份未核实前不启用生产，不创建本地替代目录绕过输入合同。

### 依赖、模型与服务

核心开发安装不含完整 GPU 模型栈和模型资产。按对应[硬件部署说明](../deployment/rtx3090ti-ubuntu/README.md)准备依赖，核对权重注册摘要、目标 GPU 引擎和必要的质量认证。

需要智能理解时，准备用户选择的服务与模型，在“AI 服务设置”验证真实连接；把凭据放入环境变量或受保护的未跟踪存储。服务连接验证只证明该次请求，不证明视频分析质量。

安装服务前确认实例名称、端口、克隆目录与配置归属。Ubuntu 服务模板必须先渲染和静态验证；不要直接安装含占位符的模板，也不要为安装本地服务停止另一实例。已有服务配置不同或任务仍活动时，先完成任务并由管理员明确安排切换。

### 投产清单

- [ ] 当前源码、站点配置和模型身份已登记。
- [ ] 解释器、固定依赖、FFmpeg、GPU 和引擎通过目标平台检查。
- [ ] 输入来源、挂载身份、索引、设备绑定与空间预留通过验证。
- [ ] 需要的模型凭据和 Web 认证由当前用户安全持有；无密钥进入日志。
- [ ] 服务进程与本次配置摘要匹配；存储与队列可见，阻断原因为空。
- [ ] 本次真实模型、真实视频、质量与浏览器成果分别留下对应回执。

## 3. 输入与任务提交

“新建实验”包含“导入视频”“命名实验”“确认分析方式”“开始处理”。至少提供一路第一人称和一路第三人称，所有机位属于同一次实验，机位 ID 唯一。CSV 为可选时间映射；独立时钟应提供对应时间戳，不能跨机位混用。

视频已登记到站点采集索引时，使用“选择采集批次”，核对封口、路数、片段、时间和角色。索引入口直接读取登记原片，不重复上传。对自动监控站点，按部署配置检查当前阶段和暂停状态，不把旧完成记录当作本轮全流程验收。

索引外视频使用“选择文件”或“选择文件夹”。核对输入文件、视角、总大小、归档名称与最终确认区。服务器按实际大小和其他活动任务预留检查容量，上传按确认字节续传；中断后继续原任务，重新选择完全相同文件。

提交后登记任务 ID、归档名称、输入方式和时间。不要把密码、密钥或完整现场路径写到公开任务名称与截图中。

## 4. 观察运行与恢复

“任务进度”显示任务状态、业务环节、资源与执行记录。`queued` 表示等待资源，`running` 表示正在处理；状态同步提示异常时，不能用旧画面判断任务已结束。

正常流程依次覆盖原片留存或索引引用、预检与时间对齐、实验发现、实验片段、关键素材、证据验收以及报告。具体启用的环节与暂停阶段取自本次配置和任务回执。设备日的原片、录音和转写保留在所属设备/日期，不用其他日期补齐缺失证据。

失败、中断或部分结果会保留已完成成果。恢复前核对原输入身份、配置、模型、阶段回执和缓存摘要；只能复用通过校验的内容。服务或主机恢复后先确认队列与租约状态，不另建重复任务。

需要查看设备日视频模型用量时，使用私有配置和实际日期：

```bash
python -m visioncortex.multimodal_usage --config /absolute/private/site.yaml --date YYYY-MM-DD
```

该命令查看本地请求账本。供应商返回的已知用量、未知尝试、进行中请求与历史复用应分开记录；未知不能记作零费用。预算与缓存策略需明确配置，其实现不能证明实际质量或未核实的供应商折扣。

## 5. 浏览器成果验收

从“实验记录”打开本次实验，逐项检查：

| 结果页 | 验收重点 |
| --- | --- |
| **视频与操作步骤** | 边界合理，第一/第三人称与对齐视频可播放，时间对应一致 |
| **录音与转写** | 本次来源、实际转写、缺失或失败说明可追溯 |
| **关键素材** | 事件、对象、时间、视角、画面事实和模型提示对应；保留证据不足 |
| **日报与报告** | 事实、文本与 PDF 一致；阶段性结果不显示为完整结论 |
| **分析记录** | 执行与复用次数、耗时、用量、质量门禁与错误来源可追溯 |

“关键素材库”和“实验室日报”是跨档案入口。空列表或没有通过筛选的事件不等于没有实验活动；候选、场景采样和伪标签不能替代人工真值。

## 6. 文件与交付登记

以本次回执和 `storage.archive_root` 确定归档位置，不假定管理员电脑路径。手动实验归档至少核对：

| 文件或目录 | 验收要求 |
| --- | --- |
| `JSON-Config-Files/pipeline_status.json` | 完成状态与实际任务一致 |
| `JSON-Config-Files/Stage-Receipts/` | 实际执行阶段有对应回执 |
| `JSON-Config-Files/evidence_package.json` | 权威证据与来源身份存在 |
| `JSON-Config-Files/evidence_package_eval.json` | 本次证据验收结果与缺口明确 |
| `JSON-Config-Files/run_metrics.json` | 实际阶段耗时、调用/复用和用量可追溯 |
| `Experiment-Clips/`、`Key-Materials/` | 视频、素材、时间戳与 sidecar 相互对应 |
| `JSON-Config-Files/daily_report_manifest.json` | 报告结果与校验和明确 |
| `Lab-Daily-Reports/`、`Professional-PDFs/` | 报告可打开，符合本次证据完整性 |

设备日归档使用独立的[设备日合同](DEVICE-DAY-ARCHIVE-CONTRACT.zh-CN.md)，不能按手动实验目录重命名其五目录结构。

交付整个可追溯归档，不只交付 PDF。填写[交付验收单](VisionCortex-交付验收单模板.md)，登记源码 SHA、配置摘要、任务和输入身份、模型回执、质量门禁、人工抽查与遗留不确定项。每项判断绑定本次输入和实际版本，历史指标不作为当前通过标准。

## 7. 日常检查、停止与升级

每日核对当前版本、配置摘要、输入索引、容量、模型身份和所属队列。出现存储身份、输入来源或服务实例不一致时停止新提交并定位。

升级前记录未完成任务、队列和当前版本，确认活动任务和上传均已结束。缺少可核实的停机安全状态时，不停止服务。独立启动的 Web 可用部署目录的 `03-Stop-Web.sh`，它会核对进程归属与活动任务；systemd 管理的实例应由管理员在确认空闲后停止指定实例。

部署经过验证的固定源码与匹配的配置、模型、注册表和认证回执，再逐项复验。回退同样恢复完整对应关系，不只替换单个文件，也不修改 SQLite 或阶段回执伪造任务状态。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 空档案、本地存储可用、视频处理待配置 | 首次本地浏览正常；真实分析前准备对应环境 |
| NAS 输入不可见或批次不可选 | 核对挂载、索引、封口和角色；不绕过输入合同 |
| 反复登录或访问被拒绝 | 使用管理员提供的账户与受信网络，核对认证策略 |
| 上传容量不足或中断 | 等待释放经批准的空间，或选择相同文件继续原任务 |
| 状态同步失败、长时间排队 | 检查所属队列和资源，避免重复提交 |
| 模型或凭据不可用 | 由管理员修复所选模型服务，不在工单粘贴密钥 |
| 对齐失败、事件少或结果部分完成 | 保留失败回执与不确定性，定位来源与质量门禁 |

不要在活动任务期间更新代码、卸载存储、换模型或强制终止进程。确定性测试、页面可见、合成结构和真实模型/视频质量是不同证据；正式结论以本次回执和人工验收为准。
