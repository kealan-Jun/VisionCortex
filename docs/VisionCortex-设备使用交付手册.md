# VisionCortex 设备使用交付手册

版本：2026-10-10
适用设备：VisionCortex RTX 3050 工作站
默认本机入口：`http://127.0.0.1:8003/#/home`；自定义端口以实际启动配置为准。

安装与生产准备以 [RTX 3050 部署说明](../deployment/rtx3050-ubuntu20/README.md) 和
[离线部署与使用交付手册](VisionCortex-RTX3050-离线部署与使用交付手册.md) 为准。
本手册介绍当前页面使用方式，不代表某台设备已经完成模型、NAS 或真实视频验收。

## 1. 开始使用

### 本机页面

完成环境安装后，按实际安装位置启动本地页面。以下使用默认安装目录：

```bash
INSTALL_ROOT="/opt/visioncortex-rtx3050"
"$INSTALL_ROOT/Start-VisionCortex.sh" --local
```

在浏览器打开 `http://127.0.0.1:8003/#/home`。本地模式使用配置中的本地目录，
不访问 NAS、不启动自动采集、不调用模型。空档案、视频处理待配置属于首次使用
的正常状态；网页打开不代表真实分析已经准备好。前台启动时需保持终端开启。

### 已准备的生产实例

部署者必须先核对私有站点配置、真实挂载身份、输入索引、存储、模型与引擎、
所选厂商凭据和适用认证回执。仓库硬件模板不能直接当作已准备的生产配置。

```bash
"$INSTALL_ROOT/Start-VisionCortex.sh" --production --config "/absolute/private/site.yaml"
```

生产启动按明确配置读取路径和设备，不自动猜测或挂载 NAS。缺少配置或运行门槛时
停止并联系部署者，不创建空目录冒充挂载，不替换已有站点地址或输入。
页面只绑定本机；端口以启动参数或站点部署记录为准。

### 应用图标与恢复

只有已按部署说明安装用户服务后，应用列表中才会有 **VisionCortex** 图标。
3050 默认服务是独立的 `visioncortex-rtx3050.service`，默认端口 8003；图标检查
该实例的健康与配置身份后打开可用浏览器。登录后自动打开页面需部署者显式设置
`VISIONCORTEX_DESKTOP_AUTOSTART=1`；登录前启动还需管理员明确配置用户 lingering。
这些行为不由普通离线安装自动启用，也不保证某台机器已经配置完成。

意外断电后先核对同一实例的配置、存储与资产，再检查服务和任务状态：

```bash
SERVICE_NAME="${VISIONCORTEX_SERVICE_NAME:-visioncortex-rtx3050.service}"
systemctl --user status "$SERVICE_NAME" --no-pager
journalctl --user -u "$SERVICE_NAME" -n 80 --no-pager
```

确认服务属于当前安装、私有配置有效、存储可用且没有活动或等待中的任务后，
部署者可按恢复流程启动该实例：

```bash
systemctl --user start "$SERVICE_NAME"
```

不要同时重启其他硬件或其他 checkout 的服务。有任务正在处理、状态不明或配置
发生变化时，先保留回执并联系管理员；不能通过重启或强杀绕过安全门。
若服务尚未安装，使用上面的前台入口，或由部署者按正式说明安装对应模式的服务。

进入页面后，选择“新建实验”，按提示导入视频、命名实验并确认分析方式；
实际分析环境未准备时，先完成配置，不能把界面检查作为模型执行证明。
关闭网页不会取消已经由后台接受的任务。断电后的恢复范围以当前队列和恢复回执为准，
逐项确认已完成环节与文件，不假定所有任务均会自动恢复。

原安装 U 盘不参与安装后的运行，可以拔出。真实分析期间保持配置使用的存储和
网络连接可用；本地页面查看不需要 NAS。

## 2. 一次任务会经过什么流程

真实分析环境已准备并接受任务后，系统按配置完成以下过程：

1. **接收素材**：登记 NAS 原视频，或将网页上传的视频保存到实验档案。
2. **检查文件**：确认视频、时间戳、视角和文件完整性。
3. **同步视角**：对齐第一人称与第三人称时间轴。
4. **发现实验片段**：扫描完整素材，定位可能发生实验的时间段。
5. **筛选关键动作**：用多视角证据筛选动作事件并保留判断依据。
6. **生成步骤理解**：整理实验步骤、参与对象与不确定项。
7. **生成成果**：输出实验片段、关键画面、关键短片、日报、PDF、JSON 和质量收据。
8. **完成归档**：所有档案完整性门通过后，发布为正式实验档案。

每个环节结束后会立即写入该环节的文件和阶段收据。处理中也能查看已经完成的内容。

### 质量门如何影响任务

- 某一个关键事件的画面或参与对象没有通过视觉复核时，该事件会被隔离并标出原因，其他合格事件、报告和归档流程继续执行。
- NAS 源文件无法追溯、视频损坏、源文件校验不一致或归档完整性失败时，任务会停止。这些问题会影响整份档案的可信度，不能跳过。
- 页面短暂读取失败只影响当前显示。后台任务和已经写出的阶段产出继续保留，页面会自动重试。
- “处理中”表示后续阶段仍在执行；“需要关注”表示应打开任务查看失败环节和已保存内容；“已完成”表示正式档案已经发布。

## 3. 页面通用组件

每个页面都使用同一套顶部栏和左侧导航。

| 组件 | 作用 | 使用方法 |
| --- | --- | --- |
| 左侧导航 | 在概览、实验记录、分析进度、新建实验、关键素材库、实验室日报和运行状态之间切换 | 点击页面名称即可切换，不会中断后台任务 |
| 收起导航按钮 | 给内容区留出更多空间 | 点击顶部左侧箭头收起或展开导航 |
| 面包屑 | 显示当前所在页面 | 用于确认当前是列表、任务还是实验详情 |
| 任务状态胶囊 | 显示是否有正在运行的任务 | 有任务时可进入“分析进度”查看详情 |
| 搜索框 | 分类查找实验、步骤、关键素材和报告 | 输入关键词后用方向键选择，按 Enter 打开；按 Esc 关闭 |
| 刷新按钮 | 重新读取任务、档案和 NAS 状态 | 页面信息长时间未变化时点击一次 |
| 左下角系统状态 | 显示网页是否连接到分析服务 | “系统状态”正常时可继续操作 |

刷新或切换页面不会重复提交任务。

## 4. “概览”页面

“概览”是进入系统后的首页，用来快速判断当前是否有工作正在进行。

### 页面组件

| 组件 | 显示内容 | 可以做什么 |
| --- | --- | --- |
| 新建实验 | 创建一个新的分析任务 | 进入 NAS 批次选择或视频上传 |
| 今日新增 | 今天新发布或更新的实验数量 | 点击进入实验记录 |
| 正在分析 | 当前未结束的任务数量 | 有数字时进入“分析进度” |
| 有报告可查看 | 已生成日报或专业报告的实验数量 | 点击进入实验室日报 |
| 需要关注 | 分析失败或中断、需要处理的实验数量 | 点击直接打开异常实验 |
| 最近完成与更新 | 最近更新的实验档案 | 点击一行进入该实验详情 |
| 工作区状态 | 实验文件和智能理解是否可用 | 任一项显示待连接时进入“运行状态”检查 |
| 成果快捷入口 | 关键素材库与实验室日报 | 直接进入对应成果列表 |

## 5. “实验记录”页面

“实验记录”集中显示已经发布的正式档案。NAS 模式下，页面顶部还会显示待分析素材入口。

### 页面组件

| 组件 | 作用 |
| --- | --- |
| 待分析的实验素材 | 提示 NAS 中存在可以选择的采集内容；点击“选择素材”进入新建实验 |
| 全部记录 | 按更新时间列出正式实验档案，支持列表和卡片视图 |
| 数量标记 | 显示当前筛选结果数量 |
| 实验行 | 显示实验名称、更新时间、片段和关键素材数量 |
| 更新时间、状态、负责人、标签 | 多个条件可以组合筛选；筛选条件保留在页面地址中 |
| 清空 | 一次移除当前全部筛选条件 |

点击实验行后进入实验详情。详情页顶部可编辑显示名称、负责人、标签和备注。这些信息用于日常查找，不会修改正式证据文件。

## 6. “新建实验”页面

这个页面负责选择输入、命名实验并创建任务。右侧“准备开始”卡会实时检查条件，条件不足时按钮保持不可用并显示原因。

### 6.1 从 NAS 采集批次创建任务

系统扫描私有站点配置明确绑定的采集目录；相机标识和人称来自实际设备配置。
同一采集会话的文件按其来源与时钟组成批次，不能把其他站点的设备映射作为默认值。
采集端保留原始视频、CSV 与自身完成信息；页面列出实际可用批次。

操作步骤：

1. 找到“选择采集批次”区域。
2. 等待所需批次显示“可分析”。
3. 点击该批次的选择按钮。
4. 在“为实验命名”中输入易识别的名称。
5. 查看右侧“准备开始”，确认有第一人称和第三人称素材。
6. 点击“创建分析任务”。

### NAS 批次卡组件

| 组件 | 含义 |
| --- | --- |
| 扫描状态 | “持续监控中”表示服务仍在定时检查目录 |
| 最近扫描时间 | 用于确认监控没有停住 |
| 批次名称与时间 | 帮助识别采集会话 |
| 第一/第三人称数量 | 两种视角都存在才允许分析 |
| 视频与 CSV 数量 | 显示当前发现的素材组成 |
| 可分析 | 文件已封口、视角完整并满足输入条件 |
| 采集中 | 文件仍在写入、另一视角未完成或设备完成信息不足 |
| 搜索批次 | 按日期或批次编号缩小列表 |

不要强制提交“采集中”的批次。NAS 短暂断开时监控会持续重试，连接恢复后会继续扫描。

### 6.2 上传电脑中的视频

操作步骤：

1. 在“或上传实验文件”中点击“选择文件”或“选择文件夹”。
2. 至少选择一路第一人称视频和一路第三人称视频。
3. 如有对应时间戳 CSV，一并选择。
4. 检查每个来源卡中的视频、CSV、视角和视角编号。
5. 输入实验名称。
6. 在右侧确认摘要后点击“创建分析任务”。

### 上传区域组件

| 组件 | 作用 |
| --- | --- |
| 选择文件 | 一次选择多个视频和 CSV |
| 选择文件夹 | 导入一个文件夹中的全部支持文件 |
| 来源卡 | 为每一路视频设置第一人称或第三人称，并关联时间戳 CSV |
| 添加拍摄视角 | 增加一张来源卡，适用于更多摄像机 |
| 删除 | 移除选错的来源卡，不删除磁盘上的原文件 |
| 角色提示 | 说明当前还缺少哪种视角 |
| 上传进度 | 显示当前文件、已上传字节和百分比 |
| 阶段列表 | 上传完成后显示后台分析进入的环节 |

大文件使用分块上传并校验每个分块。网络中断后，重新选择同一批未修改的文件并再次创建任务，系统会从已确认的断点继续；文件发生变化时会拒绝拼接。

### 6.3 “准备开始”卡

这张卡是提交前的最终检查：

- NAS 批次会显示批次编号、视频路数、片段数、视角构成和自动处理状态。
- 上传素材会显示视频数量、时间记录数量、视角构成、续传和留存状态。
- “创建分析任务”可点击时，表示页面输入已经满足提交条件。
- 按钮不可点击时，先根据上方提示补齐名称、视频或视角；若提示分析能力不可用，进入“运行状态”检查服务、NAS 和智能理解。

## 7. “分析进度”页面

任务提交后自动进入此页面。关闭网页不会取消任务。

### 页面组件

| 组件 | 作用 |
| --- | --- |
| 全部任务 | 当前任务记录总数 |
| 正在分析 | 尚未结束的任务数量 |
| 已完成 | 已发布正式档案的任务数量 |
| 需要关注 | 失败或中断、需要查看原因的任务数量 |
| 任务状态标签 | 显示正在执行的分析环节 |
| 当前环节引导 | 说明现在正在做什么，以及下一个环节 |
| 总体进度与已用时间 | 显示任务推进情况 |
| 预览已完成内容 | 任务未结束时打开已经生成的阶段成果 |
| 查看实验结果 | 任务完成后进入正式档案 |
| 查看各环节与生成文件 | 展开七个用户可理解的环节；每个已完成环节提供成果或完整清单入口 |

如果状态数据一段时间没有更新，页面会提示“NAS 遥测可能延迟”。该提示本身不表示任务已经停止，页面会继续刷新。只有任务状态明确变成“需要关注”时，才按失败环节处理。

## 8. 实验详情页面

从“实验记录”、任务预览或成果列表进入一个实验后，顶部会显示实验名称、片段数、关键素材数、分析用时和报告数量。

### 通用组件

| 组件 | 作用 |
| --- | --- |
| 编辑信息 | 设置显示名称、负责人、标签和备注 |
| 打开实验文件 | 在文件管理器中打开该实验的 NAS 目录 |
| 实验片段和步骤理解 | 分别查看第一人称、第三人称、同步双视角视频，以及实验摘要、时间边界、步骤、对象和下一步 |
| 关键素材 | 查看关键画面、关键短片、动作说明和复核依据 |
| 实验室日报 | 查看实验时间线、步骤汇总、关键动作和不确定项 |
| 专业 PDF / JSON 报告 | 打开可阅读的 PDF、结构化 JSON 和技术校验附件 |
| 页内目录 | 在当前结果页快速跳到摘要、视频、素材、报告或附录 |

处理中进入详情页时，顶部会提示“分析进行中”。此时显示的是已经写入的阶段成果，后续内容会继续增加。

### 8.1 实验片段和步骤理解

- 每个实验片段提供三份视频：第一人称、第三人称和同步双视角。
- 第一人称与第三人称可以单独播放；同步双视角用于在同一时间点对照两个画面。
- 实验整体理解说明该片段内可观察到的实验过程。
- 细粒度步骤按统一时间轴排序，逐项显示当前动作、下一步、参与对象和置信度。
- 不确定项区域保留证据不足或视角冲突，不会把推测写成确定事实。

### 8.2 关键素材

- 关键素材卡按动作事件组织，不按固定数量生成。
- 卡片可显示关键画面、关键短片、动作时间、参与对象和多视角证据。
- 点击“聚焦查看”进入大画面审阅，可切换上一份/下一份、选择 0.5–2 倍速、循环、全屏并跳到开始/关键时刻/结束。
- 键盘快捷键：空格播放或暂停，左右方向键前后跳 5 秒，P/N 切换上一份或下一份素材。
- “查看分析依据与复核信息”可展开画面事实、模型提示、对象框、置信度范围和不确定原因。
- 被隔离的单个事件会保留原因供复核，不会让其他合格事件消失。

### 8.3 实验室日报

- 顶部状态说明报告是否已经生成以及是否等待复核。
- 概览卡显示输入视角、实验片段、关键素材和状态变化。
- 时间线按实验片段展开细粒度步骤。
- 关键动作概览按实际观察到的动作类型汇总。
- 对齐、不确定项和人工复核状态在页面下方列出。

### 8.4 专业 PDF / JSON 报告

- PDF 用于阅读、打印和分享。
- JSON 用于结构化存档和系统对接。
- 网页版与 Markdown 版在已生成时显示。
- “技术附录与校验信息”包含耗时、Token、质量检查、资源遥测和验收文件链接。没有人工真值时，系统不会把自动结构检查显示为准确率。

## 9. “关键素材库”页面

该页面跨实验直接展示已有关键素材，不再只是实验目录。页面会渐进载入档案，素材较多时可点击“再显示”继续展开。

页面支持按实验日期、动作类型、相关对象和画面支持情况组合筛选；素材卡可直接查看同步画面、动作时间和所属实验，点击后进入对应实验或聚焦播放。

常见用途：

- 快速查找某次实验的关键动作画面。
- 对照第一人称和第三人称证据。
- 查看对象框与模型复核记录。
- 检查被保留的不确定项或隔离事件。

## 10. “实验室日报”页面

该页面独立列出已生成日报的实验卡片，优先展示报告摘要、实验数量、关键素材数量和需要关注的项目。点击卡片进入对应实验日报；日报尚未完成的任务应先到“分析进度”查看阶段状态。

## 11. “运行状态”页面

这个页面用于快速判断系统是否可以创建任务。

| 组件 | 正常状态 | 异常时处理 |
| --- | --- | --- |
| 分析服务 | 运行正常 | 刷新一次；仍异常时联系管理员检查服务 |
| 实验存储 | 当前配置目录可用 | 本地模式核对本地目录；NAS 模式核对实际挂载身份与网络 |
| 智能理解 | 已配置的厂商与模型可用 | 本地模式未配置属于预期；真实调用核对所选厂商凭据和模型设置 |
| 视频处理 | 当前模型和运行门槛就绪 | 本地页面待配置属于预期；真实任务失败时查看失败环节 |
| 存储位置 | 显示当前配置的实验产出和处理缓存目录 | 日常无需修改，不套用其他站点路径 |
| 运行环境检查 | 重新执行环境检查 | 仅在管理员排障时使用，运行中的正式任务不要重复触发 |

## 12. NAS 目录与产出位置

共享地址与挂载位置由部署方提供，任务回执记录实际归档根。

以下为已配置 NAS 的传统实验档案布局；本地模式使用配置中的本地归档与缓存根。
设备日档案遵循 [设备日归档合同](DEVICE-DAY-ARCHIVE-CONTRACT.zh-CN.md)，不能混用目录。
实际路径以任务回执为准。

传统 NAS 实验档案使用两个顶层目录：

| 顶层目录 | 内容 |
| --- | --- |
| `VisionCortexExperimentArchive` | 按实验名称排列的正式实验档案；处理中内容和系统收据放在独立的系统目录中 |
| `VisionCortexExperimentCache` | 可重建的处理缓存、任务状态和采集批次目录 |

处理中产出位于：

```text
VisionCortexExperimentArchive/Processing/<实验名>/<任务目录>/
```

正式档案位于：

```text
VisionCortexExperimentArchive/<实验名>/
```

常用子目录：

| 子目录 | 内容 |
| --- | --- |
| `Original-Experiment-Videos` | 原视频的零复制引用、播放列表和来源索引 |
| `Experiment-Clips` | 每个片段的 `First-Person.mp4`、`Third-Person.mp4` 和 `Aligned_First+Third.mp4` 三份视频 |
| `Key-Materials` | 关键画面、关键短片、时间戳和动作理解 |
| `Lab-Daily-Reports` | 日报 JSON、Markdown 与 HTML |
| `Professional-PDFs` | 可阅读和打印的专业报告 |
| `JSON-Config-Files` | 输入清单、时间对齐、阶段收据、运行指标和质量校验 |

## 13. 历史档案与 NAS 路径迁移

旧档案中的源路径不会被改写。NAS 目录移动后，系统通过独立路径迁移收据恢复重放：

1. 收据逐文件记录旧路径、新路径、字节数和 SHA-256。
2. 只有旧路径精确匹配时才使用映射。
3. 每次解析都会重新校验目标文件大小与完整 SHA-256。
4. 系统生成新的解析清单和解析收据，冻结的历史清单保持原 SHA-256。
5. 映射缺失、路径冲突、文件缺失或哈希不一致时拒绝重放。

迁移收据位于：

```text
VisionCortexExperimentArchive/.VisionCortex-System/Path-Migration-Receipts/
```

## 14. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 页面打不开 | 确认地址为 `http://127.0.0.1:8003/#/home`，等待数秒后刷新；仍打不开时联系管理员 |
| 页面显示服务不可用 | 打开“运行状态”；确认分析服务和实验文件状态 |
| NAS 批次一直是“采集中” | 等待文件写完并确认两台相机都完成同一次采集；不要手动伪造完成状态 |
| NAS 短暂断开 | 仅对已配置 NAS 与监控的生产实例，恢复挂载或网络后核对扫描与任务状态 |
| 上传中断 | 重新选择同一批未修改文件并再次创建任务，从已校验断点继续 |
| 创建任务按钮不可用 | 检查实验名称、视频数量、第一/第三人称视角和页面提示 |
| 任务排队 | 正常等待；显卡按队列处理，关闭网页不会取消任务 |
| 进度暂时不变 | 查看页面是否提示遥测延迟；没有明确失败时继续等待 |
| 正式目录暂时看不到 | 在任务中点击“预览已完成内容”；完成前文件位于 `Processing` |
| 从 NAS 双击视频无法播放 | 使用本机可用播放器，或在网页实验详情中播放；播放器安装由部署者确认 |
| 一个事件被隔离 | 在关键素材中查看原因；其他事件和报告会继续生成 |
| 任务需要关注 | 打开“查看各环节与生成文件”，定位失败环节并保留已有产出 |
| 历史原视频路径失效 | 管理员使用路径迁移收据解析；不要编辑旧清单或按文件名猜测 |

## 15. 管理员备查

管理员核对实际源码路径、站点配置、运行环境、队列、模型/引擎身份、存储容量及所属服务。
服务名称、账户和安装方式由站点部署确定，不能执行另一台机器的重启命令。
先确认活动任务并按流程排空，服务升级与源码更新分别记录回执。
凭据和现场日志在受限位置保存，不进入手册、截图或 Git。

## 16. 交付证据边界

网页可打开、结构检查、实际模型调用、真实视频质量、浏览器结果、恢复及长期稳定性分别验证。
使用当前固定源码、配置、模型、输入和运行环境的回执说明 `PROVEN` 范围。
缺失门槛标记为 `PARTIAL_EVIDENCE` 或 `NOT_PROVEN`，不复制历史机器的通过结论。
