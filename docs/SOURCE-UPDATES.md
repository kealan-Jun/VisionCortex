# 源码更新与版本选择

[文档导航](README.md) · [发布与部署](RELEASE-POLICY.md)

使用项目提供的源码地址获取代码。生产节点使用任务指定的完整提交身份，
不得自行选择一个较新的分支替代已验收版本。更新源码不会更新模型、运行环境或服务。

更新前检查当前仓库路径、远端、提交和工作树；存在修改时先保留并报告，
不要用强制重置、清理或覆盖消除差异。干净工作树的常规更新可以使用：

```bash
git fetch origin
git pull --ff-only
```

上述命令适用于已经配置上游的普通开发分支。冻结执行节点应获取任务指定的提交，
核对完整身份后使用固定源码和私有站点配置；活跃服务的源码不能在未排空时直接切换。

目标提交、依赖环境、模型及引擎、输入和输出位置均须核对。
[Windows 桌面源码更新](RTX4050-GIT-UPDATES.md)提供安装包的增量更新流程。
实际部署与运行验收按对应平台指南执行，历史结果不会自动迁移为当前版本证据。
