本规范依据 2026-09-10 用户确认及随后明确补充固化：所有文件夹用英文；已关闭的不完整分片按实际时长处理；录音必须保留并执行 STT；无活动抽帧是场景采样帧，不能标为五大类物理动作关键帧。它是 NAS 自动采集归档的唯一设备日目录契约，版本为 `visioncortex-device-day/1`。后续实现、页面和报告必须遵守本规范；未经用户明确变更，不得更改目录名称、层级、活动分类名称、时间单位、引用语义或恢复规则。报告正文、活动说明及原始文件名可保留中文。

### 2026-10-22 每段原片单目录与价值命名（用户后续明确变更）

MetaData/110101/rgb.mp4
ProcessedClips/Clips/110101/

  Understanding.json
  <开始>_<结束>_<类别>_<短标识>.json

保留采集端原目录名，包括 `112631_001` 等独立原片；历史平铺 `MetaVideo/*.mp4`
按原文件主名分组。未就绪原片也有对应状态目录，明确等待原因，不因此提前提交模型。
每个原片目录内的索引列出全部时间区间及其处理状态；区间文件的短标识绑定原片
身份与实际起止时间，类别写在文件名上。

| 类别 | 含义 | 视频 |
| --- | --- | --- |
| `ExperimentActivity` | 有来源与时间、帧绑定的实际模型实验观察 | 选中且校验成功后发布 |
| `ValuableNoExperimentActivity` | 有实际观察支持的非实验工作及观看上下文 | 选中且校验成功后发布 |
| `NoValueNoExperimentActivity` | 已满足确认无价值条件的非实验区间 | 不导出 |
| `ActivityPendingClassification` | 已选中活动过程，实验类型仍缺少足够理解依据 | 可先发布选中的过程视频 |
| `PendingValueReview` | 视频价值尚未判断完成 | 不把待判断当作无价值，也不据此新增导出 |

只有选中且校验成功的区间才有对应 MP4；确认无价值的区间只保留 JSON。
CV 的 `active` 与精扫活动过程边界不直接证明正在做实验；活动是否选中、实际模型
观察、实验类型和物理动作真值分别记录。类型待判断不能伪装为实验或无价值。
旧候选及失败导出目录转入隐藏 `.Evidence`，原始回执和字节通过
明确别名继续校验；只整理程序拥有的派生目录。原片、录音、CSV、时间映射和实际
筛选边界均保持原样，不拼接相邻分片，也不因为目录合并新增模型调用。
新预处理的候选帧、候选 JSON 和导出中间文件直接写入 `ProcessedClips/.Evidence/NativeClips/`，
不再临时创建公开的逐区间目录；公开目录由同一个发布服务维护。

发布采用有界批次，最新就绪区间优先。未发布视频仍显示排队、失败及具体原因，
不能仅因 JSON 已生成就声称视频交付完成。切换时逐条保留已完成执行的原回执与
来源身份，新源码使用明确完成检查点继续读取；不将旧调用改写成新版本执行，
不重发结果未知的付费请求。

### 2026-10-20 原始数据所有权、独立处理与证据边界（用户明确确认）

本节优先于下文所有历史口径。`MetaData` 和 `MetaVideo` 都属于采集端原始数据，
VisionCortex 兼容读取现场已有的两种目录。它不要求采集端改格式，不新建另一份原始目录，
不改名、搬动、重写或重排原文件；已有两目录的设备日保留两者及原引用。
本次不启用原片删除、采集清理或软链接替换；录音、CSV 和其他采集文件同样保持不动。
固定生成结果仍只有 `ProcessedClips`、`MultimodalUnderstanding`、
`LaboratoryDailyReport`、`Comment` 四类。历史交付包只有四类结果不构成删除原始目录的授权。

活动类别（实验／非实验）、视频价值（选中／确认无价值／待判定）及处理状态分别记录。
未完成、失败、结果未知、输入缺失、短片、遮挡或少量静止抽样均不能直接判无价值，
也不能单独选中生成视频副本。模型静止判断仅在已完成、清晰且有实际逐帧输入覆盖时
才允许作不另存派生视频的依据；这仍不宣称已经确证连续无物理动作。
所有已处理时段保留原时段目录、原因和原片时间映射；真实选中的实验及非实验工作视频
由独立发布路径及时落盘并校验，不再由日报阶段独占。发布失败由已有发布服务重试，
保留隐藏 `.Evidence/Retention` 回执及指数退避信息，不重复模型调用或删除历史视频。

### 2026-10-22 连续过程与细动作分开留存（用户澄清）

视频留存单位是筛选出的连续实验或有价值非实验工作过程，模型的细动作和采样窗口
不是视频切点。既有精扫审核及活动边界算法输出的活动区间，须由独立发布职责核对
已完成的 vision 回执、原片身份、原始起止时间及完整活动审核文件后导出；仅有
`ExperimentActivity` 标签仍不足以授权。不要再用多模态步骤的零点几秒边界缩短该过程。
例如原片中已审核选中的 13:58:09.900–13:59:00 应保留约 50.1 秒视频；其中 0.7 秒
面板动作仍按原时间独立记录在理解 JSON。未完成理解的尾部继续标为待理解，不能
因此从已有精扫依据的过程视频中丢弃，也不能宣称整段物理动作已确认。

非实验工作使用实际观察支持的动作及观看上下文：沿相邻输入画面保留准备、操作和
结果画面，不再统一限制为动作前后两秒。动作两侧的对象上下文延伸仍在缺失、未知、
对象消失、另一活动或大于 15 秒的相邻观察空缺处停止。两个已观察非实验工作范围
之间，可在同一已验证模型窗口内保留观看连接：两端原片时间和采集时间间隔都须不超过
15 秒，每个实际输入采样画面须有文字观察、原生 PTS 与像素绑定，采样间隙符合该窗口的
实际采样率。对象或工作类别变化、模糊画面及未知状态原样保留；连接只供观看，不确认
间隙动作、同一对象或人员身份。缺观察、像素时间未经验证、过稀采样、采集长中断或
可能的实验动作范围不得连接。同类别、具有共同对象且已选中上下文连续覆盖的工作
仍可跨模型窗口合并。没有来源依据时不能扩大到整个原片，不要求最短视频时长，
也不把静止、等待或观看连接解释为实验操作。

`latest_first=true` 时，视频导出预算同样按采集时间从新到旧分配给原片及其选中区间；
`retention_intervals` 与返回的选中区间列表仍按时间顺序保存，处理优先级不改变原片时间映射。

索引的 `retention_intervals` 保存选中／确认无价值／待判定、理由、依据及原片毫秒和
绝对微秒映射。`selected_subranges`、`core_action_ranges`、`context_subranges` 保留
各自实际范围与来源，过程视频范围与语义动作范围互相独立。实际理解、录音转写、
照片 OCR 和人员有效时段绑定独立增量发布；缺失其中任何一路不阻止已有视频输出。
目录和命名保持既有归档格式，旧视频和回执不删除、不伪装为新策略已验收的结果。

这里的 protocol 是视频中实际发生的动作步骤，在对应片段 `Understanding.json` 中呈现；
没有提供 SOP 不阻止步骤理解。历史 `Comment/Protocol.json` 继续表示参考材料，
不得将其替代实际观察。已完成窗口可以先发布，后续失败或请求结果未知保留独立状态。
后到录音、OCR、绑定只更新关联与所影响的内容，不能记成旧模型已经返回的结论。
独立 OCR 直接通过 `Comment/FieldEvents.json` 留存原读数、单位、状态、来源和关联缺口；
既有 FieldRecognition 归档是事实来源，未启用的实时接收不能声称已经上线。

### 2026-10-19 冻结展示结构与视频筛选（用户再次确认）

│           ├── NoExperimentActivity.json

采集端现有 `MetaData`／`MetaVideo` 均原位保留，不生成第二份原片目录。
活动类型是 `ExperimentActivity` 或 `NoExperimentActivity`。同一片段的相机、设备、
时间和 ID 必须一致；非活动区间没有动作关键帧，场景采样仍是 `SceneFrames`。

这里是视频筛选，只另存有价值的片段。有价值既包括实验操作，也包括非实验工作、
读数、实验等待及必要上下文。不能因 CV 未检出实验就省略有价值视频；普通静止、
重复或无关区间可不另存视频，但索引保留判断依据和原片位置。不确定或尚未处理完成
必须保留实际状态，不能把缺失视频标成已留存，也不能用抽样静止声称连续无活动。
片段价值判断明确分为选中、确认无价值、待判定。未完成理解、遮挡、覆盖或录音缺口
只能保护原片与待筛选状态，不能单独作为生成处理视频副本的依据；短静止片段也不能仅因
不足一分钟而自动选中。已存在的历史视频和回执保持可恢复，不通过本规则直接删除。

打开对应片段即可直接看到视频、图片和理解报告，不再经过 `RequestPlans`、录制编号、
执行哈希、版本或模型窗口的层层目录。技术证据放在各所属目录的隐藏 `.Evidence` 区，
编号和版本只承担后台追溯。现有不可变执行证据按稳定完整字节校验迁移，并保留旧路径
映射、可恢复记录及历史读取能力；原始音视频不因展示整理而移动或删除。

理解根目录的历史 `Understanding.json` 和 `UnderstandingReport.html` 属于旧汇总投影，
应完整验证后收进隐藏证据区并保留历史引用，不再重新生成。`Index.json` 和片段文件须
明确区分未处理、已提交待确认、部分返回及已完成；没有实际返回结果时不能用空模板冒充理解结果。

#### 仅监控 MetaData 与采集切换

私有站点配置设置：

```yaml
collection_ingest:
  discovery_mode: metadata_only
  discover_recorder_metadata: true
```

该模式只遍历归档根下各 `<日期>_<相机>/MetaData` 或 `MetaVideo`；不再探测、列举或递归扫描
外部相机目录、`lab_video` 及旧普通视频发现入口。实时监控按显式相机身份建立
同一条发现通道，原生采集子目录不再映射为另一个相机根。目录尚未出现时等待
采集端创建，状态中的 `awaiting_input` 为 true；不会创建输入目录或回退旧入口。
非法模式、关闭 MetaData 发现或无效归档根均报错，不静默转回旧监控。
`discovery_mode` 同时出现在扫描和监控快照中，便于核对实际入口。

## 字段与溯源

| 对象 | 固定数据含义 |
| --- | --- |
| `recording_id` | 原生采集记录的稳定标识；采集源位置、完成状态、签名保留在 retention 回执中 |
| `segment_id` | 采集标识、处理版本、起止时间、活动分类的确定性标识；重试不随机增加同版本片段 |

五类动作固定指手部与物体接触、物体移动、液体移动、容器状态变化、设备面板操作。现有扩展的移液器源到目标操作保留在事件回执，不改写为已看见液体移动。动作关键帧、场景采样帧、原视频、截取视频和模型输入都保留真实素材引用。CSV 插值不等于已验证原生 PTS 或跨相机精确对齐；单设备记录不宣称恢复了多视角物理动作真值。

多视角投影在独立后台工作线程更新，复用已完成检测，不调用新的 YOLO 或云模型。新分片到来时复用未改变的媒体探测和实验导出；缺失原片、损坏时间戳按来源记录，其他可读分片继续。播放优先读切分片段，片段不可读时回退到其自身 MetaVideo 的对应时间窗口；单路缓冲或失败不得阻塞其他可用视角。

下面的历史执行阶段名称继续保留，已执行旧任务维持其原有依赖和回执身份。

1. **retention**：确认采集已关闭并发布、文件稳定，校验复制原片和附属元数据，发布留存回执。`capture_complete` 只描述采集质量，不是是否允许分析的开关；已关闭的 incomplete/partial 分片同样留存并进入后续阶段。
2. **vision**：每个停止写入的采集分片独立入队，**以实际视频时长处理，不要求满15分钟**。短片、末尾不足15分钟及采集程序标记不完整但已关闭稳定的片段也处理，原始质量问题随产物保留；仍在写入的文件等待稳定，无法解码的文件保留具体失败原因。采集文件按实际起止时间形成处理批次，不再人为按900秒切出尾部小批次；精扫仍仅覆盖候选活动区间。设备按有界工位并发。先粗扫，覆盖合格且没有候选活动则跳过精扫；有候选时只对候选区间精扫。粗扫阳性仅扩大精扫范围，候选和拒绝原因保留在审计回执，不能直接命名“有实验活动”。接入现有精扫、移动画面核验、动作审计、连续状态、可观测性和边界规范化规则，只有通过设备级活动边界判定的区间命名为有活动。跨视角正式实验门禁单独保留，不因按设备归档而绕过。
3. **stt**：与 YOLO 并行；新分片消费独立音频输入回执，历史任务继续消费原片留存回执。独立录音或原视频内嵌音轨必须进入已配置的 STT。3090 Ti 在 2026-09-17 恢复本地识别后，按用户随后恢复阿里云额度并要求提速的指令，选择 `fun-asr-flash-2026-06-15`；按实际录音时长分有界窗口，保存句段、词级时间、原音频引用、模型身份和执行回执，生成第五目录的机器comment。无音频保留 no_audio；模型识别结果为空保留 no_transcript，不能据此证明静音；只有明确的语音活动检测结果才可标 no_speech，不伪造模型调用或识别文本。STT失败不占用或阻止YOLO工位。
4. **understanding**：消费落盘视频片段与STT产出。有活动按有界窗口理解步骤；无活动用稀疏抽帧描述场景及其他可见行为。两者都结合对应时间的人的comment、STT机器comment和protocol，保留输入、输出、帧来源及用量。定时抽取的模型理解图片统一标为 scene_sample；不得因为模型引用了一张图片就把它提升为五类动作关键帧。语音内容不能独立确认视觉动作；时间缺少依据时显式保留估计/未验证状态。
5. **report**：消费总索引中的关键帧文字、STT和多模态理解，重组成一份按时间组织的实验室日报。HTML 和 JSON 是一份报告的两种表达；不是三份报告并列或文本机械相加。

供应商原始转写不改写；完全落在声明缺失区间内的文字不进入机器 comment，另存排除原因及原回执引用；跨越中断的文字携带质量范围，时间对齐继续标为 `PARTIAL_EVIDENCE`。
全部为补静音时记录 `no_usable_audio` 和未调用模型，不得写成模型检测到无语音。原始录音、CSV、元数据、已有回执及设备/日期身份保持原样。

五个执行阶段使用独立 SQLite WAL 持久化队列，保存在配置的本地 runtime 根目录；NAS 仍为五个产出目录。历史任务依赖关系为 retention → vision、retention → stt；新分片为 input-vision → vision、input-stt → stt，归档独立调度，验证归档与预处理结果后正式发布，再进入 understanding → report。文件级互斥、任务租约和原子文件发布支持重启续跑。完成且输入、代码、模型及产物校验一致的阶段复用；YOLO 扫描和多模态响应另以实际输入及模型身份校验复用，缓存复用与本轮新模型调用分别记录；录音晚到不会重新运行不变视频的YOLO，comment/protocol/STT变化使理解与日报重新产出。失败保留为 failed，付费模型请求不会在每轮轮询无穷重试。

自动处理消费现有 NAS 采集批次监控发布的持久化清单，不另起重复扫描。监控发现已关闭稳定的分片后唤醒处理队列，各设备可处理分片独立推进，不等待整个采集会话或全部相机完成。网页沿用 NAS 批次卡片，显示各设备原片留存、YOLO、STT、多模态、日报状态与耗时、队列积压和归档入口。生产自动发现从 `device_day.start_date` 开始；指定历史日期可通过 CLI 补跑。新处理发现不继承旧 UI “每相机只取最近32条”的截断，已入队记录不会因后续扫描不可见而消失。全局发现上限及读取错误必须在状态中呈现；达到上限不能视为扫描完整。

10 台设备 × 每小时 4 片 × 8–12 小时 = **每天 320–480 片**，入队速度约 **40 片/小时**。队列记录各阶段待处理/运行/失败数量、待处理采集跨度、已知的实际媒体时长、未知时长数量、最老等待时间与实测服务率。480 条持久化恢复测试只能验证队列契约，不能替代连续 8–12 小时真实稳定性测试。粗扫 FPS、精扫 FPS、实际推理吞吐、视频解码与素材导出耗时必须分开报告。

## 直接读文件的全局时间检索（2026-09-17）

每个设备日的 `Comment/TimeIndex.json` 是轻量文件检索入口，不需要启动网页或调用 HTTP。
原有 `ProcessedClips/Index.json` 增加 `time_index.path` 引用；原字段、五目录及素材位置不变。
每阶段发布索引时同步原子更新；后台每五秒检查晚到的图片和索引变化。尚未有视频的设备日也可发布图片引用。
这里的五秒是轮询间隔，不是 NAS 写入到全部模型完成的时延承诺。

文件检索投影使用 `visioncortex-file-time-index/2`（原设备日 v1 契约不变）。
`streams.video` 只包含原视频、处理后片段、片段元数据引用和采集时钟映射；
`streams.audio` 只包含原录音、`transcription.sentences[].text` 原始机器转写及转写文件引用；
`streams.images` 包含动作关键帧、场景采样帧和语音拍照图片；
`streams.multimodal` 单独引用融合解释的 Input.json / Result.json，不能作为纯视频观察或录音原文。
融合解释和模型生成的帧说明不嵌入视频、音频、图片索引。各类输出通过同一个实际采集时间查询关联。

各组按全局 Unix 微秒时间排序。每项的 `start_us` / `end_us` 使用左闭右开区间，
`start_time` / `end_time` 同时给出带 +08:00 时区的可读时间。查询区间 `[a,b)` 时筛选
`start_us < b and end_us > a`；时间未知的条目保留 null，不能强行对齐。
`file`、`audio`、`source_video`、`transcript_file` 等引用使用 `path_base` + `path`：
`device_day` 表示当前设备日目录，`capture_root` 表示原始采集根。
客户端可将 `path_bases.device_day` 替换成自己的 NAS 挂载前缀；相对路径不变。

无需网页的全设备时间查询命令（也可用 `--index` 指定一个或多个设备索引）：

```bash
: "${VISIONCORTEX_ARCHIVE_ROOT:?Set the verified site archive root}"
: "${VISIONCORTEX_QUERY_TIME:?Set an absolute time with timezone}"
python -m visioncortex.device_day_file_query \
  --archive-root "$VISIONCORTEX_ARCHIVE_ROOT" \
  --at "$VISIONCORTEX_QUERY_TIME" --duration-seconds 1 \
  --output ./TimeQuery.json
```

结果 `matches[].streams` 分别给出匹配的视频、音频、图片、多模态文件引用。
视频 `file_offset_seconds` 优先使用已发布的 CSV 时钟映射；导出片段减去原片截取起点；
无活动区间沿用原片路径和偏移，不伪造已导出视频。音频偏移使用音频自己的开始时间。
缺失的时钟范围不能外推成可用视频，返回 null 和明确状态；原生 PTS 及跨设备精确对齐仍未验证。

recording 条目区分 `transcription_status`、`transcription_outcome` 和 `model_invocation`。
`no_transcript` 表示识别已执行但没返回文字，不能当成“没处理”或“没有人说话”。audio 条目保留
`capture_complete`、`quality_status`、音频自身采集时间、相对视频边界的 `audio_start_offset_us`
及原始音频元数据引用。音频晚于视频开始不自动证明丢包，具体缺失情况以采集元数据为准。

生产仍只导出固定 `process_since_us` 及以后（含跨越切换点的分片）的文件检索条目，不补跑历史。
照片按采集文件名提供秒级时间，并显式标记时钟未验证；机器转写准确率与跨设备精确时钟对齐仍需真实验收。
生成文件与模型调用成功不等于物理动作确认，也不等于自然语言检索质量通过。

## 日期隔离

一个设备日只消费该设备该日期的采集记录、录音、comment 与 protocol。历史补跑按日期分别生成输入清单、执行回执、质量说明和日报。9 月 1 日缺少录音时必须如实记录 no_audio；其他日期的录音不得补入该日期，也不得用其他日期的 STT 成功证明该日期流程完成。跨日期的总队列仅表示任务调度，不能替代单日验收统计。

## 固定报告模板

设备日报使用 `VC-DEVICE-DAY-REPORT-V1` 适配契约，栏目和顺序直接读取现有 `VC-LAB-DAILY-REPORT-V2`：今日概览、实验简报、关注事项与交接、耗时与模型用量。适配契约保留单设备观察与五类动作/场景帧区分，不冒充 V2 的正式双视角验收。原有 V1/V2 模板文件不回写。多模态理解报告使用 `VC-DEVICE-UNDERSTANDING-REPORT-V1`：理解范围、时序步骤与场景、comment/protocol/录音来源、不确定项、模型执行与素材溯源。

两类 JSON 均保存模板 ID、版本、SHA-256 与渲染器 SHA-256；日报同时保留基模板 ID 和 SHA-256。模板栏目由代码固定，模型只填结构化内容。模板呈现不新增模型调用和 Token。

网页沿用 NAS 采集批次监控，并提供 `/#/capture` 导航入口；设备日页面 `/device-days/<日期_设备名>` 对应同一五目录，支持视频区间、帧图片和原录音查阅。实时上传优先于显式历史补跑，同一优先级按 FIFO 处理。空间不足时暂停接收新的原片留存，保留排队任务和已归档结果，采集端删除仍关闭。

## 最终命名与短片段连续调度

用户最终命名要求：所有展示目录、子目录和文件使用英文，采用大驼峰 PascalCase，每个单词首字母大写，无空格、无排序序号；扩展名小写。日期、设备原始标识、时间范围以及作为数据主键的确定性标识原样保留。原始一级目录沿用采集端实际的 `MetaData`／`MetaVideo`；其余四个结果目录固定为 `ProcessedClips`、`MultimodalUnderstanding`、`LaboratoryDailyReport`、`Comment`。原始目录内部不执行重命名。历史结果子目录为 `Audio`、`Metadata`、`Clips`、`SceneFrames`、`KeyFrames`、`ClipUnderstanding`、`Stt`；关键帧的动作子目录由既有 action_type 去除下划线并将每个单词首字母大写。模型窗口使用实际片内起止时间命名，不使用序号。

0–5、5–7、7–10 分钟这样的连续短片独立入队，不拼接、凑批或补齐到15分钟。每个 GPU 处理名额独立领取一个分片；有空闲名额立即补入下一片，不等待其他分片结束。默认最多2个并行视觉分片，复用现有模型池；该上限是资源控制，不是已验证的最大硬件吞吐。多模态、STT、原片归档和报告有独立并发名额，旧手工流水线与自动视觉组共享 GPU 预约锁。

3090 Ti 生产监控每5秒进行下一轮扫描，关闭发布的文件稳定5秒后可被发现；一条采集记录检查完成即递交处理，不等待整批扫描或其他相机。复制前后再次检查身份并验证哈希。扫描、网络和复制耗时另计，不能宣称上传后固定5秒内完成YOLO。无空间时保留持久待办，采集端删除继续关闭。

### 当前语音识别选择与本地保留（2026-09-17 用户变更）

语音 provider、模型与运行位置由所选配置明确绑定。可选本地实现和云端适配器保留各自身份；切换必须显式配置，不因失败静默回退。云端识别只发送所选配置允许的有界派生音频窗口，原始音频与同设备时间引用保持不变，实际并发受资源限额约束。账户可用性与模型实际调用按本次回执记录，不能套用历史账户状态。

### 设备内活动筛选与物理动作确证

手工实验入口与 NAS 设备日入口共用算法核心，区别仅限于输入组织、调度和产物发布。两者调用 `actions.fine_scan_windows` 规划精扫窗口，调用 `actions.build_view_activity_intervals` 生成各相机的活动区间，并复用 `candidate_index` 的精扫覆盖核验、轨迹衔接及本地索引位置解析。运行中的 SQLite 索引位于配置的本地 runtime 根目录，关闭数据库连接后才将快照归档；不得在 NAS 上运行 SQLite WAL。设备日入口保留既有第一人称运动召回与开放词汇粗扫门禁，命中候选的短片沿用既有整段精扫策略；未命中候选且覆盖合格的片段仍可快速通过。

活动连续性同样由共享核心处理：精扫活动证据作为起点，按照已有实验间隔及上下文扩展上限，关联具有共同物体或轨迹的精扫观察；有物体依据的粗扫运动仅用于衔接精扫观察，不能单独开启或延长活动边界。保存衔接依据及被引用的候选，剩余区间作为无活动结果留存。手工入口将同一活动区间写入审计产物，设备日入口据此导出片段；两者均不因此修改正式物理动作的接受状态。按设备独立运行不等于已经完成多相机联合对齐和确证，后者仍需独立的真实多视角验收。

单设备片段筛选不能把“未通过跨视角/语义物理动作确证”直接等同于“无实验活动”。保留原有粗扫、精扫、动作审计和五类动作关键帧规则；已有精扫接受事件，或达到既有强上下文置信度、持续时间、观察数且包含接近/释放变化的精扫接触证据，可以在相交粗扫范围及精扫边界内界定设备活动片段。只有粗扫检测、弱接触和静态邻近不作为这类片段依据。`device_activity_decisions` 保存候选与事件引用、起止时间、依据、置信度和 `physical_action_confirmed: false`，不修改原事件的 accepted 状态，也不因此增加动作关键帧。未通过确证的物理动作不作为正式动作结论；单设备活动召回仍需真实视频质量复核。

音频元数据出现 NAS 读取错误时，视频只依据已核验的 RGB 与配对 CSV/就绪说明继续预处理；音频保持 pending_publication，保存 read_errors，禁止假定无录音或使用其他设备/日期的录音。附属采集文件由独立发布任务补齐，不能占用完成原片留存后的 YOLO 唤醒路径。

### 动态相机通道与自动恢复（2026-09-11）

启用 `device_day.camera_lanes` 后，原片及采集资料归档、YOLO、录音 STT、多模态理解、日报分别按已发现且已绑定视角的实际相机建立通道，不固定相机数量。每个阶段同一相机同时领取一个分片，按采集时间推进；其他相机无需等待。阶段间通过持久化结果衔接，预处理不等待云端理解。GPU 的批大小及单通道解码并行度仍受资源配置限制，实际吞吐需运行回执验证。

NAS 监控按相机分别扫描当日新增数据和历史数据，历史文件读取阻塞不阻塞其他相机或该相机的当日发现。闭合短片按实际长度入队。相同处理版本失败自动尝试最多三次；百炼明确返回 Arrearage 时隔离云端理解和 STT，保留待办，原片归档和 YOLO 继续。系统每十五分钟至多进行一次连接恢复验证，验证成功后自动恢复云端调度，不需要人工重置整批任务。网页独立显示预处理完成与全流程完成。采集端删除保持关闭。

### 单设备动作关键帧的筛选范围

单设备关键帧与完整实验分段分别准入：已通过现有正式 CV 审核、属于五类物理动作、位于该设备活动时间范围且未被状态机标记为重复组成动作的事件，使用与完整实验入口相同的关键素材去重和覆盖预算算法筛选。完整实验段或实验组为空不再自动清空这类动作素材。选择窗口仅用于素材预算，不作为已确认实验段或跨视角实验组发布。待复核、被拒绝事件及普通场景采样不得因此提升为动作关键帧。保留原有 PARTIAL_EVIDENCE 和 physical_action_confirmed: false，CV 准入不替代动作语义确认。回执保存 key_selection_summary 与 key_selection_decisions，目录与 v1 索引语义不变。

### 采集边界与实验时间线

采集分片是调度与溯源单位，不是实验开始或结束的依据。单设备活动审核不调用要求第一、第三人称配对的实验组构建；正式多视角实验入口继续使用原有门禁。片段保留原片引用、局部时间及采集时间映射后的 `start_us` / `end_us`，供同一日期的连续时间线关联。相邻分片本身不能证明属于同一实验；实验员身份需要对应时段的真实绑定信息，不能从相机名称推定。跨分片完整实验恢复仍须单独验证，不能以单片审核通过代替。

### 吞吐与证据留存约束

检测明细及扫描回执在后端封存后，可以通过原有 `audit_artifacts` 引用共享，不为每次下游重试再复制同一份明细；被回执引用的扫描文件属于留存证据，不能作为可随意清理的临时缓存。历史复制式回执继续可读。进程内可在文件身份和预期摘要均未变化时共享成功的完整性校验，重启、文件身份或摘要变化后重新校验。单阶段任务在自身产出后更新日索引，不为已发布的前置阶段重复重建。

相机通道数量仍动态发现。原片大文件复制可通过 `device_day.retention_io_workers` 单独限制 I/O 并发，0 表示不额外限制；视觉、录音和理解通道不继承该复制上限。当前 3090 Ti 配置复制上限为 2，以减少复制与视频解码之间的 NAS 竞争。采集端删除继续关闭。


### 调度版本与归档供给（2026-09-11）

调度轮询、相机轮转和索引呈现不再通过整个 runner 文件摘要使已完成产物失效；执行函数采用跨 Python 版本归一化的 AST 指纹。完全相同的当前执行实现映射回迁移前代码摘要，保持现有五阶段任务键不变。实际执行逻辑、输入、模型、阶段配置及原有依赖文件变化仍使相应键改变。新增执行函数必须纳入身份函数的依赖覆盖，不能用调度修改掩盖产物语义变更。

同一调度优先级下，相机以持久化的最近领取时间轮转，同相机内部按采集时间依次处理，仍禁止同阶段同相机同时领取多个分片。大文件 I/O 上限仅限制同时复制数量，不再让较早日期相机耗尽所有归档机会。原片归档完成即解除对应 YOLO 前置条件，不等待其他相机或云端阶段。

### 历史完成回执的只读读取（2026-10-20）

`visioncortex-completed-execution-bindings/1` 的既有语义保持不变。显式的 `/2` 清单另可登记 `receipt_only_historical` 理解读取项，读取算法为 `visioncortex-historical-receipt-reader/1`，原生产证明为 `visioncortex-native-r2-producer-proof/1`。它们是经过单项审核的完成结果读取权限，不授予旧供应商或当前供应商任何新执行权限，也不是执行哈希兼容别名。

清单分别冻结原生产源码、供应商设置、原生执行键、完整旧上下文与输入摘要、回执摘要和原生产审计，以及当前读取源码/配置、当前记录全文、原留存记录全文、父回执、队列版本及关联增量。两份明确记录分别服务当前调度入口与原留存发布入口，不忽略字段、不重写源身份。初版关联增量仅允许新增 `events=[]` 和 `field_event_status=no_archive_for_camera_day`；新OCR事实、备注、音频或其他原模型输入变化均须另行审查，不能声称旧模型已看过新增内容。

分拆服务使用不同有效配置时，可以在单项清单中显式登记 `reader.runtime_profiles`，最多16个具名配置。每项仅保存 `name` 和实际 `reader_identity` 摘要，名称唯一且排序；发布服务的基准 `reader.identity` 必须是其中一员，整份名单由 `reader_key` 绑定。读取身份的准确范围是完整递归 Python 源码、`device_day` 全文（仅排除 `completed_execution_bindings`、`completed_stage_receipts`、`completed_vision_receipts` 三个清单自引用）、理解阶段原 `settings_snapshot` 中的 MLLM 配方设置、`archive_root`／`local_cache_root`／`local_runtime_root` 三个存储路径与采集 `source_root`；不能声称函数还绑定了所有无关的全局配置。运维独立叠加证明另对八份实际完整有效配置的摘要逐项审核。实际读取进程必须精确匹配一个已审核的完整读取身份，不能忽略完整性、重试、准入或发布设置，不能按服务名放行。发布证明始终绑定同一基准身份和同一只读描述符，不因进度或Web进程读取而改写；读取身份范围内的未知配置、名单变化或源码漂移一律隔离。未提供此字段时仍沿用原有单一完整读取身份，显式空名单或空值不能退回默认放行。此名单只授读取权限，原生产身份、全部来源与产物校验以及禁止模型执行的边界保持不变。

读取时验证原/留存源、全部父与理解产物的实际字节、时钟及来源引用；保留既有隐藏证据映射读取能力。队列版本和当前记录必须精确一致，完整校验前后队列快照必须稳定。任何证据缺失、字节变化、当前输入/配置/读取源码漂移、新提交未知请求或关联增量越界均隔离该读取项，绝不回退为任何供应商调用，不重发结果未知的付费请求。此端口不重新入队，不直接改变队列完成状态。该记录的原生产和全部前置阶段均保留为只读，不自动重建任何父回执；普通处理入口返回 `historical_read_only_publication_required`，仅现有发布/重放入口可使用经过完整校验的读取结果，此返回状态本身不表示已发布或完成。
