# 有界回执投影与流式 JSON

基于 `6d5c84b`。生产分析仍有较高内存峰值；已观测到回执投影单行约 5.7 亿字符、单日约 12.3 亿字符。原实现同时保留整天原始对象、序列化列表、再次解析的结果列表；写索引和计算身份时还创建完整 JSON 字符串和 UTF-8 副本。

## 实现

- `ReceiptProjection.iter_records` 每次验证并暂存一个阶段文件，读取与验证的是同一份文本；逐记录写入可重建的本地 SQLite 投影，再逐条解析输出。NAS 读取发生在写事务之前；失败回滚整日更新并清理临时文件。原 `records` 小数据接口保留，生产 `refresh_index` 使用显式关闭的迭代器。
- 暂存复用现有本地运行目录，是自动清理的临时缓存，不是新权威数据集。数据、原始回执、NAS 路径和五目录契约未迁移；不存在静默截断、丢弃诊断或修改活动分类。
- `digest` 与 `atomic_json` 使用标准库增量编码，UTF-8 批量缓冲约 1 MiB。保留原排序、缩进、Unicode、浮点、NaN 拒绝规则、最终换行以及 fsync/原子替换。此缓冲不限制调用方原始对象或单个超大字符串的大小。
- 376 项相关测试通过；失败测试覆盖坏 JSON、读失败、SQL 中途失败、非法值/循环引用、fsync 失败、旧文件保持、阶段读取不占用投影写锁和逐条释放。变更文件 Ruff 与编译检查通过；全仓 Ruff 保留原有 `rtp_receiver.py` 两项问题。

## 实际回执对照

在相同环境、隔离进程中处理两份现有生产回执快照，共 21,456,862 字符；不是模型精度数据，也未修改源回执。

| 范围 | 旧版峰值 RSS | 候选峰值 RSS | 旧版耗时 | 候选耗时 |
| --- | ---: | ---: | ---: | ---: |
| 读取、摘要与 JSON 写入 | 273.40 MiB | 98.84 MiB | 1.029 s | 2.612 s |
| 投影全量和单记录增量往返 | 188.91 MiB | 109.85 MiB | 1.339 s | 2.451 s |

RSS 分别下降约 64% 和 42%。候选增加 CPU/临时缓存开销，不宣称更快。首次候选投影耗时 6.842 秒，随后避免重新序列化每个审计字段降到 2.451 秒；保留原回执，不覆盖失败或旧测量。

46,014,038 字节 JSON 输出逐字节一致，SHA256 为 `c72861994b27e13612f5a09cb9fb303cab8e9ff45607b54ca0e480b12ef9a53a`；规范化摘要均为 `8659807daaeb8b4445dea20be1978c4ccbfb81c126e727161119ee9597fe9c46`。两条完整投影与增量更新结果的摘要也一致。

原始快照、测量、测试和部署回执位于已核验 NAS `LabPrism/evaluations/receipt-streaming-20260924-v1`；代码和模型本地。本次不训练、不替换模型、不更改 GPU 配额。生产仍按角色/阶段使用第一人称 v8、第三人称精扫 v5m / 粗扫 v2。

`PROVEN`：所测真实回执保持字节/身份和事务行为，同时降低独立进程峰值。`NOT_PROVEN`：主机所有内存峰值、源对象常驻量、所有未来设备日大小，以及长期 OOM 全部消除。生产部署和模型实际加载证据与这些局部测量分别记录。

临时目录在正常退出和 Python 异常回滚时自动清理；强制断电或 SIGKILL 可能遗留临时缓存，不会因此变成有效回执或跳过完整性验证。
