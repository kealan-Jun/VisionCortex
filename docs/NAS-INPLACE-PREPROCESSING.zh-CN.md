## 状态与正式发布

沿用五个阶段队列、device-day v1 和五个 PascalCase 目录，不改变采集程序或协议。
新分片的输入、结果和归档状态分开持久化：

| 状态 | 权威回执（配置的 local_cache_root 下） | 含义 |
| --- | --- | --- |
| 采集输入就绪 | `device-day-receipts/<设备日>/<recording_id>/input-vision.json`、`input-stt.json` | 视频与音频各自通过封口、设备日期、路径、稳定性和实际内容摘要验证 |
| 预处理完成 | 原有 `vision.json`、`stt.json` | 对应模型/处理结果及素材已经持久保存，不宣称归档完成 |
| 归档完成 | 原有 `retention.json`，增加 `input_bindings` | MetaVideo 原素材已复制、fsync、独立读取校验及原子提交，绑定具体输入版本 |
| 正式发布完成 | `publication.json` | 已验证归档、预处理产物及内容绑定后，原子更新 `ProcessedClips/Index.json`；不代表真实质量验收或稳定发布资格 |

`input-state.json` 是较小的生命周期/计时投影，页面队列接口返回 `input_lifecycle`。
只有视觉结果完成而归档未完成时显示“预处理完成，等待归档”。结果仍保存在既有素材目录，
不会增加第二套正式归档目录；在归档门禁通过前不把这些素材加入正式设备日索引。
STT 结果可以先落盘；音频未验证归档时，其转写不会成为正式索引内容。
附属文件仍通过既有 CaptureFiles 发布任务补齐。

原片签名不再以采集路径迁移作为模型重算依据。保留既有 recording_id，封存设备、日期、
角色和来源内容 SHA-256；路径是读取位置。模型产物从首次生成起使用最终 MetaVideo 引用。
视觉扫描目录继续按内容、模型和扫描配置定位；召回计划在新输入上下文中排除物理读取路径。
原生帧回读保留原检测账本和原生时间戳，只在内容验证后重绑定读取位置，并记录原账本来源。
STT 的请求通过内容绑定的本地位置回执解析原音频；迁移只更新位置回执，不改变请求、窗口或
句段断点的身份。实际物理路径仍保留在来源回执中。

处理前验证内容和文件身份，处理后再次核对设备号、inode、大小、mtime、ctime及解析路径。
发现替换、变化或处理中消失时阻止受影响的发布，保留已完成回执、失败尝试和断点。
采集文件已经消失时，只有独立验证过的同内容 MetaVideo 才能作为恢复输入。
同名目标内容不符时拒绝覆盖，不把不同输入版本拼接在一起。

## 调度和外部保留规则缺口

检查了当前采集发现代码、配置、README 与设备日契约；它们没有提供外部采集端的保留期限、
清理触发条件或循环覆盖承诺。上传会话的七天过期设置不适用于外部采集原片。
因此默认 `capture_retention.seconds: null`，状态为 unknown，不解释为永久保留。

默认优先视觉预处理；结果成功或失败后都允许后台归档，避免预处理错误卡住素材保护。
等待超过 `archive_max_wait_seconds: 900` 也可归档。**900 秒是本系统的调度等待上限，
不是采集文件的保留期限或保证开始复制的 SLA**；资源占用、I/O 错误仍可能延后执行。
已知临近过期或存在清理风险时立即提高归档优先级，不等待预处理。

可由确认过采集方规则的管理员显式配置：

```yaml
device_day:
  inplace_preprocessing: true
  nas_io_slots: 3
  archive_copy_workers: 1
  archive_copy_bytes_per_second: 8388608
  archive_max_wait_seconds: 900
  nas_io_timeout_seconds: 3600
  capture_retention:
    seconds: null
    cleanup_risk: false
    safety_margin_seconds: 3600
    cameras: {}
```

`seconds` 的口径为对应媒体的实际结束时间加保留秒数，必须由采集方确认后填写；
可通过 `cameras.<camera_key>` 覆盖，或在全局/相机规则中用 `by_kind.video`、`by_kind.audio`
分别设置相同的三个字段。音频结束时间未知时不会借用视频结束时间编造其到期时间。
现有调度记录也支持视频或 audio 元数据中的显式 `source_expires_at`（Unix 秒）和
`source_cleanup_risk`；不要求采集端增加字段。按已知最早到期来源排序，其他未知来源仍显示缺口。
未知保留规则下可以显式设置 `cleanup_risk: true`，使归档先行；这不授予修改采集文件的权限。

同一 `local_runtime_root` 的自动设备日处理与归档共享 SQLite I/O 预约。
当 `nas_io_slots > 1` 时，长读取最多占用 `nas_io_slots - 1` 个名额，为归档保留一个共享名额；
总占用仍不超过 `nas_io_slots`。单名额配置沿用公平排队，不创建零容量资源。
等待者每 30 秒老化，复制各块继承该次整文件复制的排队资历，避免每块重新落到长读取之后。
等待检查优先只读，临近租约到期或实际领取时才写库。新原片复制有独立全局并发上限，
以 8 MiB 块让出 I/O 名额，并按共享带宽预约限制持续复制速率（允许有界块突发）。
旧任务和附属文件复制也参与并发预约；其旧复制实现不获得新分块限速承诺。
这些是协作式限制，无法控制采集程序或其他软件的 NAS 流量，不构成实际吞吐证明。

3090 Ti 配置启用 `device_day.latest_first: true`：各阶段在前置条件满足后，保留相机公平轮转，
同一相机按采集时间从新到旧领取，不受四小时窗口、跨午夜或旧 `BackfillPriority.json` 影响。
归档仍优先保护明确的清理风险和保留截止时间；未知截止时间的旧任务不因入队早或等待老化压过新分片。
已领取任务自然完成，不被新片抢占；完成回执、尝试次数和有效租约保持原样。
关闭该选项恢复原有分档策略，不清空历史队列。多模态仍需归档、视觉、转写及正式发布校验通过。

精扫的长期 SQLite 快照和 JSONL 检测账本保存在配置的 `storage.local_cache_root`（生产为 NAS）。
本地只保留当前构建所需的独占临时 SQLite/WAL，发布完成或失败后清理；审计读取已验证的 NAS 账本。
不把活动 WAL 数据库直接搬到 SMB。旧执行器遗留索引不在代码升级时自动删除，应在确认无人使用、
所需正式副本可恢复后单独清理。队列、锁和小型运行状态仍需本地文件系统；此改动不迁移全部历史缓存。

内存紧张的主调度进程可显式设置 `device_day.stage_worker_limits`，按阶段限制任务数，
例如 `{retention: 2, vision: 2, stt: 2, understanding: 2, report: 1}`。
上限也作用于按相机扩展的槽位；独立实时 worker 仍有自己的一个槽位，并共享原有跨进程资源预约。
可设置 `device_day.admission_min_available_gib: 4`：主调度和独立实时 worker 在可用 RAM
不足时暂缓领取新的视觉、理解和日报任务，返回 `waiting_for_memory`，不取消在途任务、
不消耗等待任务的重试次数，语音和归档继续。省略这些配置保留原行为。
该检查是协作式准入，并非操作系统内存硬上限，也不保证其他程序或单个任务不会耗尽内存。
切换代码时须先保持实时 worker 可用，再让旧主调度自然排空；不能靠强杀或低于现占用的
硬内存限制释放工作内存。可读索引发布器最多保留四天、估算 128 MiB 的来源对象缓存，
超大单日可发布但不保留热缓存；这不限制活动解析峰值，也不等同于整个进程的 RSS 上限。
回执投影另限制单条合并 JSON 为 64 MiB、两百万解析事件和 128 层深度。超过限制时
延期该日派生索引重建，保留旧索引、日报、权威回执和未确认的发布 journal；原因写入
本地 `device-day/ReceiptProjectionDeferred`。正常日期继续处理，不截断证据或伪报发布成功。
这些历史超大回执仍需后续分解或流式处理才能恢复该日刷新，不能把延期视为积压已解决。

封口内容摘要只信任本程序读取的字节。复制时同时计算摘要，fsync 后独立读取目标验证；
同进程只在完整文件身份与预期摘要不变时复用验证。视频/内嵌音轨共用已验证内容。
跨进程或重启后重新校验，不持久化仅凭 stat 的信任。模型调用本身、源内容封存和目标持久化
检查分开计时；输入验证、解码/推理与嵌套粗精扫计时不可直接相加成总耗时。

## 兼容迁移和恢复

不清空或重建旧队列。已有已完成归档、视觉或 STT 执行回执的任务继续走历史执行路径；
包含未完成模型检查点的旧任务也保留原身份。只有未开始模型、未完成归档的旧任务在领取时
增量建立新输入状态；失败的旧归档回执先保存在 history。旧队列记录原位修订调度版本，
活动租约、OS 阶段锁和完成回执防止并发重复执行。

存储适配代码只对审查过的精确文件摘要保持旧执行身份，未知源码仍使相应身份变化；
新输入路径自身纳入新的执行/内容契约摘要。生产配置中仅更新 Qwen 适配器固定摘要以匹配
位置解析实现，不改变提供商、模型、粗精扫参数或 NMS；旧已完成 STT 的语义键按精确映射保留。

归档失败不撤销预处理完成；预处理失败不复制已经验证的目标。模型回执与发布日志先落盘，
索引发布可独立重试。发布日志只有在所有分片阶段锁都可取得时才确认完成，避免一个并发阶段
误清除另一个尚未完成阶段的恢复记录。恢复不会重新调用已经完成且通过验证的模型窗口。
元数据损坏、来源版本变化和目标冲突保留失败原因。临时不可用可恢复存储后重试；
文件身份已经改变时保持阻断，需核对原版本，或使用已验证的同内容归档恢复，不自动覆盖或把新版本套用旧结果。

软链接替换保持关闭；只有原生 NAS 链接和采集读取器兼容性均验证通过，且该分片归档、预处理
和正式索引持久发布，才能沿用既有原子替换授权。仍不等待理解或日报。音频、CSV和其他外部
采集文件不得删除、移动或改写。

  尚未进行真实运行验证。外部采集保留/清理/覆盖规则仍待采集方提供。
