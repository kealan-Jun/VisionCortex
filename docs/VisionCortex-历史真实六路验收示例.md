# VisionCortex 历史真实六路验收示例

> 用途：展示真实六路运行应该怎样记录耗时、Token 和证据边界。<br>
> 来源：[六路 3 小时验证耗时与 Token 报告](validation-performance-report-2026-08-13.md)。<br>
> 当前版本结论：`PARTIAL_EVIDENCE`，不得作为当前 SHA、3090 Ti 或现网服务的通过证明。

## 1. 为什么只是历史示例

这份记录使用六路、3 小时真实视频，保留了连续运行耗时和最终验收包的服务端 Token
usage。但当前环境无法读取当时的 NAS 正式归档，因此不能重新核对全部回执；当时
记录也不自动覆盖当前代码、配置、模型、GPU、Web 上传和 NAS 服务。

| 事项 | 证据结论 | 说明 |
| --- | --- | --- |
| 当时存在一次六路 3 小时真实视频处理记录 | `PROVEN`（限原报告口径） | 原报告明确输入类型、连续总耗时和阶段耗时 |
| 当时最终验收包的豆包 usage | `PROVEN`（限原报告口径） | 37 次调用全部成功，Token 取服务端 usage |
| 浏览器上传到归档完成的全耗时 | `NOT_PROVEN` | 视频当时已在本机可读，不是浏览器上传进入 |
| 当前 SHA 的真实视频质量 | `NOT_PROVEN` | 必须在当前冻结 SHA 重新运行并人工抽查 |
| 当前 3090 Ti 的生产性能 | `NOT_PROVEN` | 历史记录不能跨机器直接外推 |
| 当前 LAN、NAS、队列恢复和续传 | `NOT_PROVEN` | 需要现网服务和当前归档直接回执 |

## 4. 两个耗时口径不能混用

最终验收包后来复用已验证的 CV 账本，重新生成模型理解与媒体，耗时
`572.156170` 秒。这个数字不是完整预处理性能，不能把其中 `81.237808` 秒描述为
全量预处理。

把全量预处理 `694.056768` 秒和最终验收后处理 `490.721011` 秒组合，可得到审计等效
耗时约 `1184.777779` 秒（19 分 44.778 秒）。它是组合口径，**不是一条连续运行记录**。

## 5. 按当前版本重新验收时怎么填

不要复制上述“通过”结论。复制[交付验收单模板](VisionCortex-交付验收单模板.md)，
至少重新记录：

1. 当前完整 Git SHA、生产配置、模型认证回执及其 SHA-256。
2. 当前真实视频的输入指纹、机位角色、时长、字节数和任务 ID。
3. 浏览器上传（若使用）开始时间、完成时间和真实端到端总耗时。
4. 当前 NAS 归档绝对路径及全部关键回执。
5. 当前服务端 usage 中的模型 ID、成功/失败调用数和输入/输出/总 Token。
6. 当前版本的多视角对齐、边界、参与对象框、步骤理解和报告人工抽查。

只有这些当前证据均可读且通过，才可把相应条目标为 `PROVEN`。
