# 实验视觉软件状态与验证依赖

统一工程的 Git 项目名为 VisionCortex。视频、读数和实验业务模块位于同一源码树，使用现有后台、鉴权接口、数据库及[统一留存合同](unified-retention.zh-CN.md)。本地部署目录可有客户名称，但客户身份、资产清单、地址、凭据和原始业务数据不进入 Git。

本文是能力和验收边界说明，不是现场运行日志。功能实现不表示部署配置已激活；模型返回不表示语义正确；一次实际链路回放不表示多设备全天闭环验收。

当前职责仅含识别、处理、实验设备／面板与样品／材料批次关联及留存，不接收或等待上游实验员身份。下文保留的人员接口、投影与历史测试只说明兼容能力，人员绑定、交接、说话人身份和人员全天轨迹均不属于本工程的接入或验收条件。

本次统一移植已完成选定算法／兼容检查、隔离PostgreSQL主动扫码与Comment专项、原生0／180度与双路隔离等窄联测；材料上下文继承修正后仅复查受影响项。未重跑旧模型、容量或历史基线。通用代码与默认入口已在独立轻量依赖环境完成安装／导入检查。继承源码仍保留原风格及部分FR静态告警，统一全量静态检查尚未通过；本次提供供整合的源码候选，不宣称正式安装包或现场验收版本。

## 证据层级

| 层级 | 可以证明什么 | 不能据此推导什么 |
| --- | --- | --- |
| 软件实现与隔离测试 | 接口、状态机、租约、幂等、错误门槛、历史和发布逻辑可执行 | 真实模型准确率、现场身份正确率、全天成本 |
| 真实输入回放 | 原件读取、原 PTS/像素、有限模型调用和部分消费链确实发生 | 未观察部分、其它视角、完整业务语义或独立样本质量 |
| 真实业务验收 | 在明确来源/身份/时间/参考与完整覆盖下核对质量和整链成本 | 不能由前两层自动升级，未知和缺测仍需保留 |

同一连拍、重叠窗口、多个变换或同一原事件的派生副本不增加独立样本数。助手视觉复核与独立业务参考要分别标识；看不清的读数、动作数量、来源身份或边界不能填成真值。

| --- | --- | --- | --- |

| 主动扫码与口述转换 | 已实现同一 Core 的原图 QR 任务消费、主动扫码上下文、自动 ASR 候选与结构化口述消费 | 选定 fixture 专项已验证，包含材料的同 scope 事件时间继承与阶段/整体完成区分 | 明确扫码意图的实际生产事件、可靠 ASR/NLU 解释、双来源现场链与 NAS 发布仍未验收 |
| 视频价值、边界与模型对照 | 粗细规划、覆盖/盲审任务、独立流租约、原帧交付、完整片段登记、离散帧映射与既有 worker 框架 | 有限真实候选响应、严格结构验证及失败保留 | 双轴价值候选已进入任务、查询、日报及关联侧车；分类/边界质量、全时段覆盖、组合增益及正式发布仍未验收 |

连续 OCR 的 `confirmed` 只指视觉门槛。后台推断的动态关注不等于操作声明，但实验员主动扫码设备本身就是该时刻的操作声明，应立即建立当前上下文。主动扫码与被动入镜不得混成一种事件。材料关联/候选仍不等于用量事实。值为空、身份未知、无模型、配准失败和所有结果不确定都必须如实报告；“拒绝所有输入”本身不构成算法成功。

屏幕工程还提供默认关闭的移动字段跟踪、尺度兼容重定位、首次质量短等待与笔画变化补读。局部原片回放已核对同帧数字／点位候选、读数状态变化、旧案例缓存复用及精确事件复放；缺少当前帧点位的结果仍待定。几何通过数不等于读数正确数，尚无独立真值、完整全天或普遍屏幕类型的通过结论。源码同步不启用这些研究策略，也不切换现有生产服务；设置和限制见[算法文档](lab-vision-algorithms.zh-CN.md)。

新增显式相机设备策略允许原图/连续视频中的设备码被相机看见即作为操作锚点，不要求手持扫码器或逐次手工声明。它只作用于已启用的来源种类、方向、已激活设备及可信时间；原默认被动观察行为保留。重复同码是持续出现，不能切换开始/结束状态；A→B→A 保留三个阶段。阶段开始/结束与来源固定的口述解释配对，15分钟分包及跨日不结束阶段。未知身份、时间、多个码和缺少口述锚点分别保留。软件阶段包络及原片范围索引不表示已裁剪视频或证明包络内持续操作。

通用 `producer-ingress` 角色读取既有只读生产清单，按原相机 ID、完成回执及精确选中片段映射进入同一 Ingest/Timeline，不将两台测试相机写成产品范围。首次启用默认只建立历史基线，随后处理新完成和晚完成的数据；历史回放须显式限定。缺少原生片段映射保持 pending，不能将15分钟原包当成已筛选片段。该角色需要明确启动，未暗中加入旧 `all` 角色。

视频模型的实际请求和执行回执可携带有界历史先验，以及已经持久的同时间段 ASR、OCR、来源二维码正文。领取视频任务时可等待已提交的相关辅助任务；未来数据、其它相机、未支持的人员/面板关系和当前模型回答不进入先验。未知世界时钟只允许同一原件或已登记精确来源映射下的相对偏移证据，不借接收日期建立人员轨迹。未校准的结果也可留存，接收日只决定归档分区，物理事件时间保持未知。

## 闭环的实际接入条件

1. 明确来源范围：两台采集设备就是两路来源，不据此建立两台仪器；登记采集视角、会话和原时钟依据，不要求人员信息。Receiver 自报 online 还要核对所选主码流的新鲜度和实际可解码性，不能把旧帧当当前画面。
2. 区分操作锚点与普通观察：主动设备扫码，或明确启用的相机设备策略下的有效设备码，可建立相机/设备/时刻上下文，不等待视觉动作。其它后台观察仍是候选。主操作设备不覆盖所有面板，切换设备不结束旧实验。
3. 接入口述 Comment 与真实计算：规范口述携带实验过程语义，连同原音和转写范围，与扫码历史、视觉动作及 OCR 组织到同一物理时间线，不要求说话人身份。按显式策略保存正文、原媒体/时间范围、实际输入与执行回执；没有音频、模型或消费证明就不填成功。near-time 不等于同一实验。
4. 回到实验与材料：设备扫码建立的当前上下文关联已有实验/目标制备批次；材料扫码按历史解析材料单元与来源批次并指向该目标。一个目标批次允许多材料、多设备。显式目标优先，否则只继承同一精确人员/相机 scope 内、事件时间严格更早的明确目标，并保存来源扫码引用与快照；没有上下文才待关联。晚到声明不悄悄重挂旧材料。关联不确认用量，授权数量业务仍走原 Core/command 事务。类别清单不建立材料实物，识别不扣量，未知初始量不变成零。
5. 发布并回读：按四个既定结果目录和 `Comment/Audio`、`Comment/OCR` 六字段关系写出原件引用、候选、日报与历史，区分计划、写入、回读和业务确认。
6. 由同事整合 Agent 界面：通过既有鉴权 API/command 读取证据和提交授权确认/更正，保留历史。工程不新增公开 tool 协议、独立 MCP 服务、界面产品或第二套账本。

这些条件有先后依赖，可以并行准备不依赖现场的部分；不能因为一个远端历史回收尚未闭合而停止本地可完成的软件工作，也不能借此跳过真实证据门槛。

已有 Timeline、语音候选与 `TimelineEvidenceBundles` 可以保存和只读导出有历史关系的原文证据；这不等于规范口述已经自动正确分配到所有实验。未知时钟、说话人不足、并发实验及口述/视觉冲突须继续显式保留，自动跨模态消费和真实联调尚未全验收。

人员日视图已通过同一数据库日报快照派生，保留设备切换、来源／目标批次及原媒体链接，并区分主动操作声明、明确关联、实验相关证据和历史佩戴来源。选定隔离专项覆盖跨相机、人员交接、晚到标签复用、并发实验、口述计划及未知时钟。它是已有事件的投影，覆盖仍为 partial，不证明全天连续轨迹、说话人、位置或实际动作次数；真实多设备联动仍须验收。

`timeline-operator-scan` 与 `timeline-operator-context` 已通过既有鉴权 command 入口实现，并完成选定 fixture 专项验证。它们不是新的 Agent 工具/UI 协议，也不等于自动扫码入口或实机链已验收。

口述转换另按阶段范围处理。“某样品在天平前配制已完成、现在去烘箱”是 `stage_complete` 加 `next_stage_plan`，样品、批次和实验运行保留；到下一设备主动扫码后才改当前设备。阶段或设置声明不归档，只有明确整体全部完成才产生 `experiment_complete` 并允许授权整体结束/归档。

[`comment_transition.py`](../../src/visioncortex/lab/comment_transition.py) 已实现接收结构化解释的薄接口，入口为 `timeline-comment-transition`。它固定原 speech 正文指纹、原音 evidence/version/范围、源时钟与精确 scope，并消费上游已持久化的 `reviewed_note` 解释记录。该记录可由获授权的 Agent 服务产出，不新增用户手工确认流程；接口不硬编码自由中文来猜结束，也不独立证明 ASR/NLU 语义正确。选定 fixture 专项已验证，自动入口、实际 ASR/NLU 消费及实机 NAS 跨模态闭环仍待集成与验收。

## 晚到、正文与版本

晚到证据使用原事件时间与明确媒体偏移，不按入库时间重写物理顺序。关联和报告追加新修订，并保留知识时间，能够分别查询“当时所知”和“后来更正”。标签回收、容器换料和人员交接跨边界时，不用最新关系覆盖旧视频。

证据正文是实际原文或候选结果，可能包含错误或不可信文字，不作为系统指令执行。只读导出核对实际数据范围、模型/观察版本、完整来源引用和精确历史绑定；正文缺失或冲突的项目须待核验。数据库引用验证、源字节回读、本地 HTTP 负载验证和模型逐请求消费证明是不同维度，不能互相替代。

原件、不可变观察、确认和更正的历史不删除。最新日报可更新，但内容恢复为早期文本也仍是后来的一版。实验归档是技术记录状态，不证明物理实验结束，不因下一次扫码、文件边界或超时自行释放资源。

## 夜间处理成本

已有阶段计时和预算软件，当前不能给出代表性全设备日通过结论，也不能从小片段推算可靠全天 ETA。需要同时核验采集完整性、模型质量、全时段覆盖、未分析间隙、报告/归档完成以及次班积压。

整链计时应包括读取与源核验、解码、模型加载和推理、ASR/OCR、队列等待、检查点/数据库、日报、存储写入与完整回读、失败重试。嵌套或并行阶段不能简单相加成整批墙钟；未测项为 `null`，不是零。既有选中片段完成也不表示全部原始时段已筛查。

在未提供实际班次前，只比较显式的 8/10/12 小时预算，不臆造交接时刻。共享模型的独立状态轮转不是张量批处理；重放同一来源的负载路不增加独立质量样本。进程资源、框架分配/保留内存与共享整卡峰值分开记，独立时刻峰值不能相加。服务在线或显存有余量不证明持续多路业务容量。

## 已补齐的消费与刷新

本次 OCR 接入选择 PP-OCRv6 的明确版本与本地权重。模型服务支持显式 ONNX 全图检测/识别或给定字段区域识别，并固定主服务与处理器源码身份；后者不证明自动面板定位。历史 PP-OCRv5 结果保留作对照，不随新配置重跑。屏闪、读数变化、关键笔画/小数和设备归属仍按真实连续来源分别验收，模型换代本身不构成通过。

新增可选的 LCD 定位 → 原像素裁切 → 同一 PP-OCRv6 → 空间字段候选路径，接在既有 `TimelineRunner`，仍输出 `Comment/OCR` 与原日报／查询接口。`panel_ocr.py` 使用显式清单校验的单类别静态 ONNX 图，CPU 执行；`panel_fields.py` 只解析相邻数字、单位与 PV／SV，位置不提供实物身份。定位漏检时整图文字继续保留；整图与裁切冲突时不选定数值；仅由文字组合发现的质量／温度等候选明确标注“尚未确认属于屏幕”。通用屏幕检测不能启用某台天平的固定精度规则，原注册字段的 FR 规则路径保留。

私有 `services.ocr.panel_locator` 配置包含 `checkpoint`、`confidence`、`iou`、`max_panels`（上限24）、`padding` 与可选 `tiled_detection`；仅适用于 `ppocr-onnx`／`full_image`。定位权重、处理器源码和有效参数进入执行身份，改变配置后需更新调用方身份清单。默认不加载定位模型，不改变采集来源或 NAS 路径。现成定位器在有限实图中漏检了部分天平／液晶屏，OCR 仍出现负号和 LED 数字错误，真实读数质量未验收；不能把集成完成、空值门槛或候选数量称为准确率提升。静态照片试验也不证明屏闪恢复通过。

新部署可向既有 `TimelinePublication` 显式传入带时区的 `not_before`，仅发布该启动时刻后创建的日报快照，避免规则身份升级触发旧快照重发。历史快照与原产物保留；该限制只使用发布快照时钟，不校准或改变采集／实验时间。默认未设置时保持原行为。

`timeline-v1` 的 `tick` 消费已完成 QR 照片任务中明确的 `scan_intent`；显式相机设备策略还消费已登记照片/视频的实际解码结果。也可经鉴权命令 `timeline-consume-scan` 消费原任务。唯一已解码值才进入原设备声明命令；无码、多码、未激活设备和未知时钟保留未决。原任务的媒体 SHA、规则、相机与证据引用保持可查，重复投递复用同一来源回执。没有开启相机设备策略时，普通后台码入镜不声明操作。

本地 ASR 保存后自动生成有原音范围的 Comment 候选，后处理恢复不重复 ASR。已有来源固定的 `comment_interpretation_review` 才能自动进入原阶段转换；普通转写不自动变成已审核解释。

显式开启统一发布后，既有 `delivery` 角色消费已提交关联侧车，调用原 writer 刷新已有主日报与可变 Understanding 入口；无原生 `ProcessedClips/Index.json` 时返回 `pending_native_index`。不重跑模型、不生成新片段、不改旧执行历史。
