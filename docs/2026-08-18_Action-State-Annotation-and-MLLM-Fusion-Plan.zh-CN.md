# VisionCortex 动作状态标注与多模态融合方案

## 结论

现有 21 类 YOLO 继续作为对象定位层，不直接扩成五类动作检测器。无需新增标注即可完成的运动补偿、轨迹序列、对象约束、可观测性账本和时序多模态复核先行；只有无法从现有对象框、轨迹和短片段可靠得到的状态与关系，才进入人工标注。

## 已完成的无需人工标注增强

- 第一人称相机整体运动补偿：用稳定实验对象的中位平移抵消头动造成的全画面漂移。
- 固定设备伪移动抑制：天平和磁力搅拌器的框抖动不能单独构成“物体移动”。
- 液体转移时序候选：从同一工具轨迹提取“源容器接触—运输—目标容器接触”，但仍标记为间接证据。
- 跨视角合并约束：不同设备、不同容器家族不能只因动作类别相同而合并。
- 动作可观测性账本：逐事件记录 21 类 CV 能直接证明什么、只能间接支持什么、缺少什么。
- 有界多模态复核计划：优先复核液体、容器、面板、接触类，以及高置信但被 CV 拒绝的候选；模型不能静默修改 CV 接纳状态。
- 关键素材时序输入：直接复用已经导出的短关键片段，向模型提供第一/第三人称各自的动作前、峰值和动作后画面，不再只看单张峰值帧。

## 必须人工标注的内容

### 1. 手部与具体物体接触

不要创建 `hand_touch_paper`、`hand_touch_tube` 等大量 YOLO 类别。标注关系：

```json
{
  "hand_track_id": "hand-01",
  "object_track_id": "weighing-paper-03",
  "object_class": "paper",
  "contact_state": "approach/contact/grasp/release/no_contact",
  "start_us": 0,
  "end_us": 0,
  "visibility": "direct/occluded/not_visible",
  "supporting_views": ["fp01", "tp02"]
}
```

困难负例必须包含：框相交但未接触、手从物体上方经过、手被大设备框包围、第三人称遮挡导致的伪接触。

### 2. 液体区域与液体状态

由于实际液体多为有色或非透明液体，首轮优先标注可见液体区域和液面，而不是透明液体的复杂折射：

- 容器内液体区域 Mask；
- 液面线或液位比例；
- 颜色仅作为属性，不创建颜色专属动作类；
- `stationary / flowing / aspirating / dispensing / pouring / mixing`；
- 源容器、目标容器和工具轨迹；
- `source_level_decrease / target_level_increase / no_visible_change`；
- `directly_observed / supported_inference / not_visible`。

当容器不透明、遮挡或分辨率不足时必须标 `not_visible`，不得用实验常识补写。

### 3. 容器状态变化

采用对象属性和状态转移，不把每个状态组合扩成独立对象类：

- `open / closed / cap_on / cap_off`；
- `upright / tilted / inverted`；
- `empty_visible / liquid_visible / level_increased / level_decreased / unknown`；
- 状态变化发生时间和动作前后帧；
- 容器实例身份及跨视角关联。

### 4. 设备面板操作

需要新增小目标和时序交互标注：

- 按钮、旋钮、滑块、显示屏 ROI；
- 手指/手与控制件的接触；
- `press / rotate_clockwise / rotate_counterclockwise / release`；
- 操作前后显示状态或 OCR 文本；
- 设备实例和控制件实例身份。

不允许仅凭手靠近整个 `balance` 或 `magnetic_stirrer` 框确认面板操作。

### 5. 物体移动

通常不需要新增对象类别。只需为错误分析补少量困难样本：

- 第一人称头动而物体未动；
- 手持物体相对镜头静止、相对实验台移动；
- 多个同类试管的身份切换；
- 拿起、运输、放下和释放的阶段边界。

## 首轮标注规模

以下是验证方案的起始范围，不是生产最终量；完成首轮误差归因后再扩充：

| 标注包 | 建议起始范围 | 重点 |
|---|---:|---|
| 手物接触微片段 | 600–1,000 个 | 正负与困难负例平衡 |
| 液体/液面代表帧 | 1,000–2,000 帧 | 有色液体、不同容器、两类视角 |
| 液体转移微片段 | 300–500 个 | 源—运输—目标完整过程 |
| 容器状态转移 | 400–800 个 | 前后状态和不可见状态 |
| 面板操作 | 300–600 个 | 控制件、接触、显示变化 |

训练、验证、测试必须按实验批次/日期/操作员拆分，禁止把相邻帧随机分到不同集合造成数据泄漏。

## 多模态大模型如何参与筛选

推荐采用“CV 召回优先、多模态有界审计、证据门最终决定”的融合方式。

### 实验片段

1. Motion/YOLO 提供高召回粗边界和动作锚点。
2. 多模态模型审阅有界双视角故事板，判断片段是否完整、独立或连续，并输出起止完整性收据。
3. 模型若认为边界缺失，只能提出局部补扫请求，不能直接把时间边界改成模型猜测值。
4. 局部补扫必须在对齐时间轴上重新获得手、对象、状态或运动证据，之后才能修改正式边界。

### 关键素材

1. CV 保留高召回候选，不因模型暂时不可用而丢失。
2. 模型比较双视角的动作前、峰值、动作后序列。
3. 模型可确认、建议重分类、标记不确定或指出冲突。
4. 模型不得仅凭常识创建不存在的对象、液体、读数或动作。
5. 高置信被 CV 拒绝候选可以进入“召回复核池”，但正式晋升仍需要双视角可观察事实或局部补扫证据。

### 为什么不让模型扫描全量长视频

- 外部 API 延迟、限流和排队不可控；
- 全量抽帧会显著增加 Token、网络和墙钟时间；
- 模型输出难以稳定复现；
- 没有 CV 锚点时容易出现时间边界漂移和语义幻觉。

因此模型只处理 CV 压缩后的少量、有时间戳、有对象证据的对齐短窗口。所有调用都必须记录模型 ID、输入/输出 Token、延迟、重试次数、输入素材哈希和决策收据。

## 验收指标

必须分别报告：

1. GT 动作是否进入 Motion/粗扫窗口；
2. 是否产生 YOLO 对象框；
3. 是否形成动作候选；
4. 是否通过跨视角审计；
5. 是否进入最终关键素材；
6. 多模态模型确认、重分类、不确定和冲突数量；
7. 各层 Precision、Recall、F1 与 tIoU，不再用最终事件召回率代替 YOLO 召回率。

所有评估数据必须固定：数据集 ID、run_id、预测账本 SHA-256、GT SHA-256、代码 SHA 和配置 SHA。事件短 ID 不得跨运行直接比较。
