# VisionCortex 发布与部署

源码更新、安装包构建和服务部署分别记录结果。获取代码不自动安装依赖、
启动模型、访问生产存储或重启服务。

## 固定版本与构建

使用已审查的完整提交身份构建，记录源码、依赖锁、配置和模型摘要。
交付包校验文件清单、平台依赖、启动入口及文档引用；候选包明确标记其身份与限制。
含未提交修改的快照不能当作正式发布提交。

`Acceptance.json` 的 `commit_sha` 与构建源码必须一致，`release_ready` 必须有适用证据支持。
内容摘要证明文件身份，不能代替目标机实际运行或真实视频质量验收。

## 站点配置与数据

公开默认配置使用本地隔离目录；生产存储、设备绑定、服务地址和访问凭据由部署方
通过私有站点配置提供。私有配置、现场日志、模型、引擎、原视频、运行数据库及产出不入 Git。
缺少生产路径或存储身份验证时停止，不建立本地替代目录，不改变既有归档含义。

代码、环境、当前权重和活动数据库使用适合其 I/O 契约的本地存储。
大体积数据按站点归档合同保存；处理前核对容量、缓存上限、来源和输出目的地。
数据迁移或清理须有独立授权、内容验证与可恢复记录。

## 升级与回退

先核对当前服务、活动任务、源码和运行环境，再准备经过验证的新版本。
等待活动任务完成或按适用的排空流程交接；切换操作不能覆盖用户修改或删除任务数据。
安装、激活与服务重启分别执行并记录回执，数据库不随程序回退自动降级。

正式验收分别覆盖依赖、模型身份及实际调用、真实输入质量、归档完整性、浏览器可用性、
恢复和稳定运行。缺失门槛标记为 `PARTIAL_EVIDENCE` 或 `NOT_PROVEN`，列出缺失证据。
使用[交付验收单](VisionCortex-交付验收单模板.md)记录当前版本，避免套用其他机器或历史结果。
