# 自动处理恢复与性能审计（2026-09-23）

本轮从 `540737f9bf6b4f1819fbfc8504b80190b6136663` 出发，在独立工作树修改，
保留运行中的主工作树与生产配置。范围覆盖采集发现、归档依赖、队列与重试、
扫描规划、索引发布、进度与吞吐验收。此范围审计不等于整个仓库不存在其他缺陷。

## 已定位的问题与处理

| 问题 | 根因与处理 | 证据边界 |
| --- | --- | --- |
| 归档前置失败耗尽视觉重试 | 队列完成状态及回执身份通过，不代表文件仍然可读。执行完整校验字节；缺失或损坏前置转为 `waiting_for_prerequisite`，不算本次模型失败。恢复核验在独立后台进行，避免在调度锁内读取NAS。 | 确定性检查覆盖准入后文件消失、同尺寸损坏、恢复及真正模型失败；真实缺件无法凭代码恢复字节。 |
| 历史前置失败和过期租约滞留 | 只迁移消息精确匹配的旧前置失败，保留历史错误与事件，仅退还最后一次能证明的失败；过期租约可转等待，有效租约不动。完整复核前置后恢复。 | 其他模型失败仍遵守三次上限，不清空队列或重置全部尝试。 |
| 归档缺件不能重新留存 | 独立恢复线程确认原片稳定、来源签名一致、旧归档确实损坏后，以队列版本比较更新方式重排该次留存；同一修复身份仅一次。 | 原片和归档均不可见时保持阻塞，等待输入恢复；不复制其他视频或制造完成回执。 |
| “观测停更”与无新增混淆 | `revision_observed_at` 表示新来源版本到达，不能当轮询心跳。本轮核对时扫描心跳及20个扫描线程正常。增加独立轮询年龄、扫描覆盖与最后新版本时间。 | 正常轮询不证明上游相机持续录制，也不证明当前存在40片/小时负载。 |
| 持续验收漏计 | 原实现只取界面最近50条，历史记录可挤出实时输入。改为持久观察窗口内全部实时来源版本，并严格匹配来源签名、有效启动与发布时间。 | 尚未被观察就被新版本替换的旧来源版本不能追溯补造；跨重启时长不算连续负载通过。 |
| 规划阶段重复打开视频 | 粗扫和精扫召回改用现有有界视频读取器，复用句柄，保持时间定位检查、回退与关闭机制。新增取帧、模型互斥等待及服务时间。 | 保留模型互斥、阈值和采样选择；上线收益需真实回执，不由单元测试推定。 |
| 不可读候选帧误过召回门禁 | 粗扫错误率原先遗漏 `frame_unreadable`；现在计入既有错误率阈值。 | 保留闭集候选，读取失败不会被描述为已完成召回或无活动。 |
| 源校验耗时不能归因 | 拆分产物校验、媒体探测、时钟解析、模型验证等待与验证执行。 | 线程非CPU时间包含I/O、锁与调度，不能全部标为NAS等待；嵌套时间不可直接相加。 |
| 时间索引发布反复TypeError | 真实设备日索引首条归档失败、`start_us=None`，日报暂停时仍无条件构造目录而报错。改为仅在日报启用时根据已校验的设备日目录身份构造；单日异常不再中断其他日期发布。 | 已用真实索引复现；保留未知采集时间，失败日期不更新成功版本并可重试。上线错误消失仍需日志确认。 |
| 索引发布缓存占用过大 | 只缓存可读内容与时间索引需要的轻量投影，排除密集检测诊断数组。修改时间索引指针时，在同一设备日锁内重读完整原始索引并只改指针。 | 确定性测试确认完整CV证据保留、未变日期不重复写入；实际内存收益需上线测量。 |
| 推理池扩容失败连带整片失败 | 生产日志在精扫上下文扩容时出现显存分配失败。已有相同身份健康模型时复用该上下文，并冷却扩容；初始化超时仍保留占位，不能无限创建替代线程。 | 首个上下文或全部上下文不可用时仍失败；不改变引擎、batch或识别阈值，不能据此声称所有显存风险已消除。 |

## 不改变的生产边界

- 设备日五目录、媒体身份、时间语义、关键帧与场景帧区分、原始录音保留不变。
- 不删除原片，不启用尚未通过原生NAS软链接验收的清理功能。
- 精扫使用已接受的 batch 4 引擎；batch 16 候选仍需同输入质量和性能对照。
- 理解、日报维持现有暂停设置；其待处理需求不能被算作全链路成功。
- 扫描与召回代码指纹变化后，相关视觉产物遵守原有版本校验；历史复算单独计数，不充作新增实时吞吐。不扩充历史回执兼容名单来代替新版本验证。
- 只在独立工作树测试。上线切换与持续观测须单独记录，不以代码同步代替部署证明。

## 验收方式

确定性检查覆盖等待与恢复、真正失败预算、来源漂移、活动租约、超过50条观测、
错误心跳、读取器关闭及质量门禁。使用生产Python 3.12运行隔离测试，模型以替身验证，
这些检查不代表真实实验识别准确率。

实际吞吐按同一连续观察窗口统计到达、成功发布、真实模型执行和缓存复用，区分实时输入
与历史补跑。10台设备每小时各4片对应40片/小时；11台同频率输入对应44片/小时。
连续8–12小时负载下，完成量覆盖到达量、可处理待办与等待时间不持续增长，才有依据评估
持续处理能力。没有新增采集、服务中断、只完成粗扫、只看到GPU活动均不能替代此验收。

本轮观察到其他任务为了训练切换同一服务，相关中断必须保留并切断连续验收窗口。
