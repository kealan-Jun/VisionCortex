# 设备日实时预处理与夜间报告

生产配置：`configs/rtx3090ti-ubuntu-production.yaml`。NAS 五目录、分片时间与设备标识不变，采集源删除仍关闭。

- 已上传并关闭的完整文件按实际时长处理，不等待凑满 15 分钟或所有相机齐片。归档、YOLO、录音识别保持全天自动执行；相机通道按实际设备动态生成，资源容量仍由运行配置控制。
- 多模态理解和日报更新只在北京时间 20:30–次日 08:00 领取新任务，当前默认结束时间可配置。
- 到窗口结束时不打断已经执行的任务；剩余任务留在持久队列等待下一窗口。白天继续积累预处理产物。历史积压也在夜间处理。
- 夜间仍执行既有失败上限、供应商可用性检查和证据校验；不清空失败次数、不无限重复付费重试。
- 此规则在后台服务内执行，与浏览器是否打开无关。服务夜间恢复时自动续取任务；不需要 Codex 对话触发。

```yaml
device_day:
  night_processing:
    enabled: true
    timezone: Asia/Shanghai
    start: "20:30"
    end: "08:00"
```

`device_day_night_schedule.py` 只控制新任务准入，不改变模型、源文件、阶段结果或缓存标识。`device_day_service.py` 在调度前和执行前检查窗口。`/api/device-day-progress` 返回 `night_schedule` 供页面显示。

边界验证覆盖 20:29:59、20:30、跨午夜、07:59:59、08:00、UTC 转北京时间及实时阶段始终放行。生产夜间完整批次尚需真实运行验收；“翌日早晨全部报告完成”是交付目标，不能仅凭时间规则保证，仍取决于待处理量、模型吞吐和失败恢复。
